# 账号与会话实现契约

本文描述已实现的账号认证。角色创建及全服昵称唯一性见[characters.md](characters.md)；后续已接入[共享地图/票据](shared_world.md)与[公共聊天](chat.md)，完整持久化业务执行器仍待推进。账号名与D08角色昵称不同：登录账号采用固定ASCII规则，不修改离线昵称或资产。

## 请求与响应

所有账号路由位于已保存基地址下的`/api/v1/auth/`。携带JSON的操作只接收有界对象并拒绝未知字段，身份查询和注销使用Bearer头；响应设置`Cache-Control: no-store`，错误体为`{"code":"稳定错误码"}`，不回显请求密码、令牌或数据库错误。

| 路由 | 请求 | 成功结果 |
|---|---|---|
| `POST register` | `username`、`password` | 201，`account={id,username}`；不自动签发令牌 |
| `POST login` | `username`、`password` | 200，会话及两种令牌 |
| `POST refresh` | `refresh_token` | 200，同一会话的新令牌；旧令牌立即失效 |
| `GET me` | `Authorization: Bearer <access_token>` | 200，当前账号公开身份 |
| `POST logout` | 同上 | 204，该会话已撤销或已不存在；没有可解析令牌则401 |

会话响应包含`account`、`session_id`、`access_token`、`refresh_token`、`expires_in`与`refresh_expires_in`。ID为UUID字符串；令牌为32字节安全随机数的64位十六进制表示，不是账号ID或可预测时间戳。

用户名清理首尾空白、转换ASCII小写，允许3～32位`a-z0-9_`，数据库唯一约束防止并发抢同一账号。密码不裁剪或改写，12～128个Unicode标量值且最多512字节、不能全为空白；密码使用随机盐Argon2id，原始密码不入库。

常见错误：`INVALID_REQUEST`、`INVALID_USERNAME`、`WEAK_PASSWORD`、`ACCOUNT_EXISTS`、`UNAUTHORIZED`、`RATE_LIMITED`、`SERVER_BUSY`、`AUTH_UNAVAILABLE`、`DATABASE_UNAVAILABLE`。账号不存在与密码错误统一401；无账号服务时503，不假装认证成功。

## 持久化、刷新和注销

- `accounts`保存UUID、规范账号名、密码哈希、禁用标记及创建时间；`sessions`保存账号归属、两种令牌的SHA-256摘要、期限及撤销状态。
- SQLx迁移在启用账号服务之前完成；数据库配置错误时启动失败，不回退到临时内存账号。
- 密码验证成功后，登录锁定账号行，清理该账号过期/撤销会话，并按创建时间保留最近的 `SSJX_AUTH_MAX_SESSIONS - 1` 个会话，再原子插入新会话。默认最多保留8个；达到上限时淘汰最旧会话，不再因关闭客户端遗留的会话而拒绝登录。错误密码和禁用账号不能淘汰会话；并发登录受账号行锁保护；新会话插入失败时淘汰一并回滚。认证会话不是游戏连接，不表示允许多个角色同时上线。
- 被淘汰会话的访问令牌、刷新令牌及尚未使用的世界票据全部失效；对应游戏连接按现有会话撤销机制退出，角色与游戏进度保留。会话创建顺序使用实际插入时刻，避免等待行锁的事务以更早的事务开始时间覆盖排序。
- 默认访问期限15分钟、刷新总期限7天，由`.env`的`SSJX_AUTH_ACCESS_SECONDS`/`SSJX_AUTH_REFRESH_SECONDS`配置并验证范围。刷新锁定会话行，原子轮换两个摘要，不延长该会话最初签发的刷新截止时间。同一旧刷新令牌并发提交仅一次成功。
- 每次身份读取/刷新检查禁用、撤销和期限；注销立即撤销该会话。保留旧访问令牌的短期摘要归属：轮换后不能读取账号，但原有效期内仍可撤销所属会话，避免刷新抢先提交后导致注销假成功；不保存原始令牌。服务器重启不丢账号或已提交会话。
- 刷新响应丢失后无法取回新秘密，客户端应重新登录，不重复使用已经失效的旧令牌猜测状态；此处没有经济资产变更。

## 客户端边界

`OnlineAccount`自动加载节点独立于账号面板，仅在内存保存绑定服务器的账号和令牌。面板关闭不取消已受理账号请求或销毁会话；客户端重启不自动恢复会话或发送登录请求。有效会话到期前尝试刷新，失败退避，不无限高频重试；被拒绝的刷新清除本地会话。

地址仍单独保存到`connection.cfg`；密码输入框隐藏且提交/关闭后清空。回调只向界面传公开账号和错误码，不传令牌。更换服务器前先退出原账号，令牌不能被发送到新地址。注销网络结果未知时，仅说明本地退出，不能宣称服务器已经确认注销。

登录页提供默认关闭的“记住我”，勾选并成功登录（包括注册后的登录）才保存最后一组服务地址、用户名和密码。独立的`connection.cfg.login`使用Godot AES-256加密配置，随机32字节密钥存于同一用户目录的`.login.key`；这避免明文保存，但不构成操作系统凭据库或抵御同用户文件读取的保护。访问/刷新令牌不持久化。再次打开同一服务器登录页时自动填入，密码仍遮罩；修改服务地址清除自动填入的密码，其他服务器与local模式不能读取该组凭据。退出账号保留记忆，取消勾选立即删除密文和密钥；文件不可读时提示重新输入。UI布局、按钮层次与勾选图标均由`.tscn`/SVG资源定义。

非回环地址发送账号凭据必须使用HTTPS，不关闭证书校验或跟随重定向。HTTP仅用于本机账号开发和不含秘密的连接探测，不能据此开放公网明文密码。

## 当前资源与发布限制

初始资源边界为4KiB账号JSON、32KiB客户端响应，默认2个并行密码任务、10个数据库连接与查询/等待超时。账号请求设置有界全局/IP/规范账号名窗口：默认全局600次/分钟、IP60次/分钟、账号10次/分钟，键最多8192个。工作数、连接池、超时、限流额度与窗口已接入`.env`，具体字段见`.env.sample.txt`；窗口额度按配置窗口而非永远按分钟计量。以实际连接IP计数，不信任任意代理头。上述为当前技术起点，代理公平性和发布负载需要后续完善。

每账号默认最多8个未过期认证会话，可通过`SSJX_AUTH_MAX_SESSIONS`调整；这不是D03游戏并发策略，后续角色/WSS仍须限制一个有效游戏会话。当前尚无账号恢复、会话管理页、完整审计或公网防滥用体系，不能直接当作生产运营完成。D07和D08运营项仍按设计入口保留发布关口。
