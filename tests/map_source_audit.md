# 原版地图来源的深入静态核查

用户目标：让`res://scenes/admin/data_browser.tscn`显示更多原版单张地图，而不是只显示现有3张重建地形。结果：**本轮没有获得新的真实地形布局，不能将214条目录伪装成214张已恢复地图**。新增工作是缓存/消息输入链路证据、完整包成员审核，以及能识别内嵌和gzip/zlib封装场景的有界扫描器。

## 范围与隔离

- 仅读取`analysis/source/ssjx.mrp`及同一Online App ID 403084的5个辅助包、已解包副本、`commonRecord/version`；没有执行原始程序、联系历史服务或修改玩家数据。
- 不处理被排除的`gssjxz`和`gssxmz`。额外扫描目录中的其他App ID MRPG包也不导入。
- 不改动管理页、游戏业务、导出配置或当前未提交的怪物素材工作；分析文件在Godot客户端之外。
- 原始扩展SHA-256为`e08f93bebe133b700f2305bfbedd994b05cc8d04a5a854262af9ced956afbc03`；证据按原文件偏移标记，不将文字池当成指令。
- 旧的原版地图恢复报告及原有输入哈希保持不变，本轮报告单独保存为`analysis/recovery/maps/source_audit.json`和`.asm`。

## 可执行入口

```sh
python tools/audit_original_map_sources.py --capstone-path analysis/.python_deps
python -m unittest discover -s tests -p 'test_map*.py'
python -m unittest discover -s tests -p 'test_*.py'
```

生成JSON不依赖Capstone；`--capstone-path`仅为额外输出可读反汇编。日后取得真实Online缓存可用`--scan-root /path/to/online/cache`附加只读扫描；默认不扩大到个人目录或不相关游戏。

## 实现与验收

- 原有`parse_scene()`仍要求完整消费文件并拒绝未知尾部。新增`parse_scene_prefix()`只为从容器中框定一个候选的边界，返回候选字节长度；候选保留偏移、SHA-256、未消费容器长度和`review_required`，**不自动成为游戏资产**。
- 内嵌扫描先核对数字地图编号与已验证目录名称，再校验尺寸、两层字节、图块映射及交互记录。世界总图、数字字符串和普通图像不因此被视为地形。
- 压缩头使用重叠检测，避免前一个伪zlib头吃掉紧邻gzip的魔数；验证流结束并对大小、递归深度、尝试次数及累计解压量限额。限制命中必须写入报告，不静默报告“全部扫描”。
- 单流最多4MiB、累计展开最多64MiB、压缩深度最多2层、最多50,000次尝试；原包成员集合另有累计解码预算。额外单文件最多40MiB。未识别的格式不能据此宣称已排除。
- 测试覆盖合成场景的内嵌偏移、旧接口尾部拒绝、gzip中套zlib、重复内容、损坏/错身份/截断拒绝、解压限额、字面量及BL目标核验、本地版本表与原输入不变。

原生路径、包清单与解释见[`analysis/recovery/maps/README.md`](../analysis/recovery/maps/README.md)。`0x02001001`和`0x02000002`是特定已核对分支/调用中的数值，不等同于已验证可联机的完整协议；4字节缓存标记也不是已恢复的内容校验算法。

## 实际核查结果（2026-10-16）

- 6个同App ID原包、1,916个声明成员与现有解包副本全部一致；原始输入前后哈希相同。
- 原始容器字节及成员解压数据去重后共1,883份流。已知场景身份前缀为0、完整候选为0，扫描限额命中为0。
- `map.mrp`只含756份地形图块、26份动画/图像组及通用启动字节码，不含`.map`成员。180字节的`version`是5个素材包的版本/长度记录，并非地形布局。
- 已定位地图载荷分派、缓存写入、缓存命中和缺失时的请求构造调用链；没有新的原始场景缓存或抓包，因此本轮不增加任何“恢复完成”的地图资产，也不声称原服已恢复。
- 地图专项11项通过，其中7项为新增检查，4项为原解析器回归。合成样本只用于验证扫描器，不导出成地图；本轮未运行Godot页面渲染验收，因为客户端没有本任务的代码变更。
- 整体Python回归72项通过，原始日志在`/tmp/opencode/vssjx-map-source-audit-python.log`。该整体运行包含当时工作树中已有的未提交怪物目录测试，不将其代码或资产混入地图核查提交。

后续需要真实Online地图缓存、独立地图数据包或可核验的原始地图响应。只有取得并审核这些布局数据，才有依据让管理页增加真实原版场景预览；不能靠把756张图块任意铺排来补齐200多张地图。
