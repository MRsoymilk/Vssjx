# 原版技能恢复进度

当前能确认原版客户端技能记录格式和界面流程，**尚未找到一份实际的原服技能记录**，因此 `native_skills.json` 的 `skills` 为空，原版技能数量仍未知。现有破山诀、御剑诀、摄灵诀不是原版技能恢复成果。

后来用户提供的 [资料表](../../references/player-sheet/README.md) 已归档，含 30 个具名技能及 18 行缺名信息，补充了职业／门派与效果描述。它属于待核对的用户资料，不是原服二进制技能记录；与本页的原生解析证据分开保存。

## 已定位的原始实现

`gameonline.ext` SHA256 为 `e08f93bebe133b700f2305bfbedd994b05cc8d04a5a854262af9ced956afbc03`。

- `0x2fe50` 分配 80 字节技能结构，从数据流读取字符串 ID、名称、说明、等级、最高等级、消耗灵力、分类及战斗标记，随后读取类型化参数；并非根据资源编号查找静态技能表。
- `0x2e50e` 为该解析器注册列表回调；`0x2e5f0` 收到新技能记录后按字符串 ID 替换、插入或移除已有项。等级字节 `255` 是移除标记，记录到这里立即返回。
- `0xed38` 按技能结构 `+0x0f` 区分武功／心法；`0x2b40` 仅将 `+0x0e == 1` 的记录加入战斗可选列表。
- `0xeba0` 列表显示名称、当前／最高等级及已下发说明；`0xec8e` 从 `+0x0c` 读取灵力消耗。
- `0xdf64` 在升级前检查技能点及最高等级，再根据选择发出升级／退级请求。不能据此推定原服务端升级价格、数值、返还规则或伤害公式。
- 四类块标签 `0/1/3/6` 与八种嵌套参数标签 `0..7` 的字段读取已恢复；未知语义保持为原生结构偏移，不猜测哪个编号代表流血、控制或吸血。

原包 `teach6` 的引导文案明确区分攻击性武功和提升属性的辅助心法，并提到升级获取技能点。它是引导文案，不包含任何具体技能、等级数值或特效映射，不能代替原服技能表。

## 解析与验证

`tools/native_skills.py` 提供独立离线解析器，使用带 BE16 字节长度的 UTF-16BE 字符串和有符号 BE16 参数；拒绝截断、奇数文本长度、异常计数、未知块和多余字节。它不访问旧服务器，也不会把输入来源自动认证成原版。

```sh
python tools/native_skills.py --output analysis/recovery/skills/native_skills.json
python tools/native_skills.py --input 已切出的技能列表段.bin --output work/skills-review.json
python tools/native_skills.py --single --input 单条技能记录.bin --output work/skill-review.json
python tests/test_native_skills.py
```

输入须为原始协议中**已经确定边界**的记录／列表段，不是完整网络包、MRP、ANI 或图片文件。支持解析并不表示已经接入原版战斗逻辑。

测试使用明确标为合成数据的协议向量，不作为游戏数据发布。另用 Unicorn 运行原始 Thumb 解析器 `0x2fe50` 及原始字节、短整型、字符串和列表读取函数，仅替代内存分配和复制接口，对比真实原生结构与新解析器结果：攻击性记录、非战斗记录、移除记录均一致。设置 `SSJX_NATIVE_DEPS` 为含 `unicorn` 的 Python 依赖目录可运行这一额外验证。

完整原版技能接入还需要：旧服务器配置，或原服登录／升级／战斗时的有效技能与效果下发记录。只有界面截图或特效动画不能恢复完整技能等级、公式与限制。目前保留现有重建战斗规则，不凭空新增“原版技能”。
