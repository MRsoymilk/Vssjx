# 线上角色创建验证

## 命令与隔离

从仓库根目录执行：

```sh
cargo test --locked --manifest-path server/Cargo.toml
python tests/run_characters.py
```

依赖Rust、Godot、Docker及本地缓存的`postgres:17-bookworm`。脚本创建随机命名的临时PostgreSQL容器（tmpfs数据和随机本机端口），完成后只清理自己创建的容器，绝不读取/连接开发者数据库。显式以`SSJX_ENV_FILE=''`禁用私有`.env`，仅在测试进程中放宽限流以完成竞态/故障用例；真实默认限额仍由账号回归验证。

Godot测试使用独立连接偏好与带哨兵内容的临时离线存档，验证线上创建完全不改写它们；不读取玩家存档。测试结束清理本轮文件，恢复原路径变量。日志不得包含密码或令牌。

真实离屏渲染：

```sh
SSJX_CHARACTER_CAPTURE_PATH=/tmp/opencode/vssjx-character-ui LIBGL_ALWAYS_SOFTWARE=1 \
  python tests/run_characters.py --render
```

`XVFB_BIN`/`GODOT_BIN`可指定可执行文件；截图输出目录由脚本建立。普通headless不证明真实UI显示正常。

## 覆盖

- Rust及Godot执行同一固定昵称正反样例，覆盖大小写、普通外部空格、Unicode边界、全角/控制/零宽/内部空格和长度限制。
- 同账号同操作ID并发仅一份角色和两份初始库存行，重复请求返回相同角色与创建时结果。
- 同账号不同ID并发仅一个成功，其他返回角色上限；不同账号大小写等价昵称并发仅一个成功。
- 创建字段严格类型化，拒绝多余权威字段、重复键、非规范/非v4操作ID及非法枚举。
- 成功和明确拒绝持久化，原回执先于账号上限/新操作业务验证；相同ID换内容冲突，改变JSON空白/字段序不改变业务摘要。
- 账号回执不可跨账号读取；未登录、过期、禁用不允许创建。
- 创建等待账号行锁期间撤销会话，锁释放后必须重新鉴权并拒绝，不能继续使用最初的认证结果；角色与回执均不得出现。
- 使用仅存在于隔离库的触发器强制初始物品写入失败，证明角色和回执也回滚；撤销触发器后用原ID成功重试。
- 重启Rust后恢复角色和成功/拒绝回执；暂停测试数据库时返回503，不伪造成功，恢复后仍可重放。
- Godot验证登录入口、昵称冲突保留输入、操作中锁定、三个类型选项、退出后重新登录查看、过期禁用和不进入离线世界。
- 本机测试代理故意丢弃第一次**已提交**创建结果，返回临时503；客户端保留ID及原内容，未知时锁定编辑，第二次请求完全相同且只返回原角色，不重复发资产。
- 同一代理还模拟一次未到达后端的未知结果：关闭并重开大厅后，即使列表为空也保留原请求，只允许原ID原内容重试；后台自动刷新过程中打开页面不会卡死在未加载状态。
- 客户端清除会话后，迟到的读取响应不能重新安装原账号角色；服务端原创建回执是历史结果，列表读取则可返回更高修订的当前基本行，两者不混淆。

该验证不覆盖WSS/CharacterActor、多人互见、在线PVE、容量或公网运营发布，不代表M1全部完成。
