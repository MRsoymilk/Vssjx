## 与项目已有内容的区别

- 项目已有3,300张原包解码图、756张地图图块、117套怪物动画和14项地图物件动画。对比范围与文件摘要在 [基线清单](baseline-inventory.json)，人工审阅依据在 [对比报告](comparison.json)。角色目录和NPC配置中已有名字，不等于已有对应专用造型。
- 布袋仙人、白蛇仙、天池上人、五毒天王、齐霞儿等提供了目前尚未找到专用造型的截图候选；领土战祭台和青色回纹传送砖同样保留为缺失候选。横、竖传送砖是同一视觉资源的两种排列，不能当作两种新贴图。
- 不同NPC会复用外观：达人使者／博浪沙火鹤，齐霞儿／医者，天池上人／独指人，易静／隐名剑仙等在清单中按视觉组关联。分组为人工判断，未证明原始资源ID完全相同。
- 竹丛、棕榈、雪松、枯树、山门石柱和矿石在项目中已有同类原版图像，附上已有资源路径。它们的新截图可补充布局与身份关系，不算新恢复的原生贴图。
- 其他怪物大多在已有117套动画中能找到同类外观，没有逐个重复导出截图冒充新增怪物素材。
- “朱亮”等名字按截图目读记录；低置信名字另有标记。截图中的“铁钟道人（读字待核）”与玩家表格“钟馗道人”的读法不一致，保留分歧，不擅自覆盖原配置。玩家表格同名命中仅列为交叉参考，不能单独确认截图所在地图。
- 截图中的玩家、帮会称号、斗剑冠军、玩家坐骑、队友和战斗角色未作为新NPC导入。来源资料的姓名及标签仍完整保留于原截图。

“疑似缺失”表示在已审阅的项目目录中未找到对应资源，**不是对全部组合帧进行穷尽搜索后证明绝不存在**。这些记录没有绑定为可运行资产。

## 地形数据边界

观察JSON以原始480×800截图为坐标系，裁切框为 `[left, top, right, bottom]`，右、下边界不包含。地图视口暂按 `[0,86,480,602]` 保留，边缘仍可能含标识和游戏提示；中央常被玩家及文字遮挡。

地形裁片记录可见语义，例如 `water_grass_shore`、`lava_cliff`、`snow_steps`。截图能证明这些局部结构存在，不能证明原图行列数、全局坐标、精确图块编号、格网比例、碰撞、NPC刷新位置或传送目的地。因此 `world_map_id`、`tile_grid`、`collision`、`teleport_targets` 等字段明确为 `null`，没有生成假的 `.map` 或补造截图外地形。**99份观察不是99张独立地图，也不是99份恢复出的原始地形文件。**

## 复现与核验

```powershell
# 从已归档原图重建，无需原Downloads目录
python tools/extract_screenshot_resources.py

# 首次建立归档时才需要输入目录
python tools/extract_screenshot_resources.py --source 'C:\Users\milk\Downloads\ssjx_pic'
```

依赖Pillow。工具验证原图尺寸和SHA-256，拒绝覆盖内容不同的归档；逐个PNG核验像素等于原图裁切，并保留裁片摘要。`regions.json` 是人工审阅的输入，`manifest.json`、对比报告、观察JSON、裁片及网页由生成器维护。归档包含原文件名；同一个数字的 `.jpg` 与 `.webp` 独立保留。解码像素完全相同的重复项在源清单单列，不仅凭相似画面删除。
