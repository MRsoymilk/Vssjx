# 联机版测试与容量验收计划

计划修订：2026-10-15。本文件是联机功能的待执行验收方案，没有1000人容量结论。服务端已出现Cargo工程文件，本轮未核验其运行能力或既有测试结果。产品范围和待定项见[设计入口](../design/README.md)，阶段与[roadmap.md](../design/roadmap.md)对应，当前离线测试入口仍见[testing.md](testing.md)。本轮文档检查不等于执行本计划中的游戏/数据库测试。

离线存档不得被联机测试覆盖。测试账号、数据库、配置、压测机器人和存档全部隔离；沿用已经完成的client/路径迁移，不把测试方案当作重新迁移工程的指令。

## 2. 一致性不变量

| 编号 | 必须成立 |
|---|---|
| I01 | 每个活动角色只有一个业务协调者；换连接不生成第二份可写库存或遗忘在途事务 |
| I02 | 同operation_id同内容只产生一个终态；同ID不同内容拒绝；业务来源唯一性不依赖请求ID |
| I03 | 每个成功接纳的战斗修订只推进一次；状态、随机推进、资源和回执一致提交 |
| I04 | 同一个人遭遇最多成功消费一次；A的击败/暂停不改变B的个人目标 |
| I05 | 同一事务引起的属性、货币、库存、任务及战斗快照不能跨提交混合 |
| I06 | 已完成世界转换不能被旧world_epoch的位置保存或旧地图事件覆盖 |
| I07 | 快照完整安装后才应用其后增量；旧stream/snapshot/实体可见代次不能污染当前世界 |
| I08 | 所有队列与在途任务有数量、字节和时间边界；慢连接/数据库异常不能无限增长内存 |
| I09 | 保证范围内已确认成功的经济/任务/战斗提交在恢复后存在；未知结果不得被宣称失败 |
| I10 | 线上业务不调用离线发奖/保存路径；动画播放和界面暂停不改变服务器结果 |
| I11 | 线上全服name_key唯一且每账号最多一个角色；不同operation_id、地图/实例或并发请求不能绕过，离线存档不参与线上占名 |

测试数据库可直接查询回执、奖励来源、个人遭遇、战斗修订、余额/库存约束，不能只看UI“提示成功”判断通过。数据库写入必须经过真实事务路径，不能用mock结果代替关键一致性验收。

## 3. 故障注入与并发矩阵

以下故障仅在隔离测试环境注入，记录准确阶段、操作ID、角色版本、持久化事实和客户端表现；不能向公网真实玩家执行压测或破坏性故障。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| F01 | 买药事务已受理，旧连接断开，新连接接管，旧事务随后提交 | 复用CharacterActor，新连接得到正确余额/库存和回执；旧投递可丢，业务结果不可丢 |
| F02 | 事务提交成功后、响应/推送前断线或杀游戏进程 | 同ID重试找回原结果，不重复扣款、消耗或奖励 |
| F03 | COMMIT返回前数据库连接中断，第一轮查回执为空，原事务仍可能运行 | 标记未知/恢复中，不把空查询当回滚证据；确认原事务结束后才继续 |
| F04 | 同ID原payload重试但当前版本已更高；同ID改数量/目标/expected_revision | 前者返回原终态且不覆盖新快照，后者IDEMPOTENCY_CONFLICT；新ID旧版本才报STALE_REVISION |
| F05 | 手动、自动、重连重放及超时同时争用一个战斗revision | 仅一个有效结果，其他请求稳定拒绝/重放，无额外回合或重复结算 |
| F06 | 进入战斗已冻结地图但事务明确回滚；或提交后地图投递失败 | 前者受控解除预约；后者按数据库恢复战斗标记，不能恢复成可移动并再次开战 |
| F07 | 切图/战败回城已提交，旧位置保存迟到 | world_epoch/position_revision条件拒绝旧写，不回到旧地图或非法位置 |
| F08 | 同一私人怪物换多个operation_id/battle_id挑战；死亡后重新登录 | 已CONSUMED目标不复活；逃跑/失败仅按规则释放预约，不返还已提交消耗 |
| F09 | 背包用药、装备/卸下、购药、丢弃、战斗用药同时请求 | 同一库存串行更新，非负约束成立，容量/堆叠/所有权不被绕过 |
| F10 | 读角色后、读库存前另一写入提交；角色执行器恢复时旧写入结束 | 组合快照来自同一业务提交，或明确等待恢复；不拼接两次READ COMMITTED查询的不同状态 |
| F11 | 战斗随机计算后事务回滚/重启，最终回合推送前重启 | 随机推进和状态一起恢复，原结果未知时不重抽；最终奖励和任务只推进一次 |
| F12 | 快照分块期间实体离开、移动、再次进入；leave先到而旧chunk后到 | 临时快照/增量屏障正确；旧块不会重新添加已离开的实体 |
| F13 | 某订阅不接收其他区域事件；位置在发送前被合并 | 本订阅最终seq连续；不因地图全局号跳跃误判丢包 |
| F14 | 旧visibility_generation的update/leave在同实体重新进入后到达 | 丢弃旧代次，不删除/挪动新进入实体；生命周期事件不被位置合并覆盖 |
| F15 | 缺块、同号不同内容、摘要错误、超大快照、同步超时、同步中切图 | 废弃旧同步，有限重试或明确拒绝；不安装半快照、不静默少发实体 |
| F16 | 地图漏tick、消息入口持续满载、高频合法改目标和反复stop | 无无限Burst补发/寻路堆积，无速度增加或跨格穿墙，tick不会被输入饿死 |
| F17 | 慢接收客户端、库连接池耗尽、长事务、拥塞后集中重连 | 有界队列与超时生效，其他角色仍可服务；无无限缓存/重连风暴 |
| F18 | 打开背包/属性页、切到战斗、关闭握手时仍持续接收消息 | 网络持续poll和心跳，页面暂停不停止连接；主线程画面更新预算有效 |
| F19 | 同票据并发认证、票据过期、封禁/注销后继续发WSS命令、伪造转发头/他人目标 | 单次票据仅一次消费，权限撤销生效，归属隔离、来源信任及限流边界正确 |
| F20 | 发布新规则后恢复未结束旧战斗，旧规则缺失，数据库schema不兼容 | 使用原规则恢复或阻止服务就绪；不能静默换数值/回滚不兼容数据库 |
| F21 | 维护停机、服务恢复、真实断线60秒和在线闲置5分钟的到期前后边界、反复重连/心跳/无效指令 | 按已确认D04，断线冻结且停止自动下指令；到期按主动逃跑结束，保留已提交消耗、无胜利奖励且无战败回城处罚；服务器故障不冒充玩家挂机，换连接不重置既有deadline |
| F22 | 全新环境从备份与可用WAL恢复，模拟数据库主机/磁盘丢失 | 实测RPO/RTO并核对账本、回执、任务、战斗及版本；不以进程重启成功替代备份恢复 |
| F23 | 两个账号并发创建相同name_key；首尾空白及规范化等价样例；尝试借地图/实例或注销/封禁绕过占名 | 全服仅一个创建成功，冲突返回NAME_TAKEN；已占名不因连接/地图状态释放；非法昵称返回INVALID_NAME，不能自动加后缀创建 |
| F24 | 创建角色提交后响应丢失；同operation_id原昵称重试、同ID改昵称、明确重名拒绝后换新ID新昵称 | 成功重试返回原character_id、不误报NAME_TAKEN；同ID改内容报IDEMPOTENCY_CONFLICT；确定失败不残留半个角色或资产，结果未知不自动换ID再创建 |
| F25 | 同账号不同operation_id并发创建不同昵称；不同登录会话尝试顶号；离线角色与线上使用相同昵称 | 数据库保证每账号一个角色，其他创建报CHARACTER_LIMIT_REACHED；不同登录会话第二次上线被拒绝；离线昵称不参加线上查重，不修改旧离线存档 |

增加归档回执重放：RESULT_ARCHIVED仍能确定原终态，不再次执行；若将来上线操作代际退休，必须测试旧代际拒绝后才允许清理去重记录。非法/未认证消息不应大量生成数据库回执记录。

| 运维/安全 | 会话撤销、限流公平性、配置摘要、日志脱敏、备份、维护及发布兼容 |

必须覆盖当前UI内隐藏的业务规则：未接任务不能挑战、前置不足不能传送、NPC恢复的距离、领取奖励并恢复、调息扣5铜钱、升级恢复、门派/签名保存、战败恢复与回城、60格/99堆叠及卸装容量。背包整理只改变显示顺序，丢弃按服务器堆叠身份/数量而非格子索引，关闭窗口不得离线覆盖线上资产。

在线完整路线仍为“领任务→三只山狼→领取奖励→灵门→遗迹妖王”。固定随机测试使用显式给定取值，不把Godot与Rust相同seed当作等价性证据。客户端动画未播放/被跳过时，业务结算仍一致。

`--headless`不能代替真实画面验收。Linux真实渲染可沿用Xvfb与OpenGL/Mesa的现有工具；大规模服务器负载主要使用不渲染的协议机器人，真实客户端只验证画面、帧耗时和玩家体验。不要以1000个Godot窗口作为主要压测方式。

## 5. 容量口径与预算

D01已确认以全服1000人正常混合游玩为目标，单实例同可见范围热点独立验证和报告；D02已确认首版不自动分线、不按人数隐藏本应可见的玩家。报告必须引用这一决策口径，并分别列出空闲连接、全服混合玩法、单实例热点和客户端显示容量；已确认目标不等于已有性能结论。

静态预算必须记录假设：N人全互见、同步频率f、每个实体更新实测平均s字节时，下行估算`N × (N-1) × f × s`。N=1000、f=10、s=100得到999 MB/s约7.992 Gbit/s，这只是未含其他开销的估算，不是性能实测。实际测试记录压缩前后字节、实体投递量和网络出口，不能只看WebSocket帧数。

### 5.1 负载样本（待冻结）

| 场景 | 起始建议 |
|---|---|
| 空闲 | 1000个完成认证和同步的连接，按真实心跳；不计作玩法容量 |
| mixed-v1草案 | 60%持续合法移动、20%PVE、15%空闲/查看、5%背包/NPC交互；聊天叠加且不改变角色占比 |
| 移动参数 | 机器人每2秒左右更换合法目标并加抖动，遵循速度/服务器路线，不只在原地发心跳 |
| 战斗参数 | 指令间隔取服务器最小间隔与2秒中的较大者并加抖动；记录活动战斗数、成功指令数和结算数 |
| 背包/NPC参数 | 约每5秒一次合法购买/使用/恢复等操作，资源不足的拒绝单独计量，不用无效请求充当成功吞吐 |
| 正常聊天 | 全服每秒1条作为起始样本，独立记录广播接收数；最终按使用预期冻结 |
| 聊天上界/滥用 | 合法个人限额叠加、突发刷屏、单发送者占用；验证全局预算和公平性，而不是要求全部恶意请求成功 |
| 单实例热点 | 单独阶梯增加同一可见范围人数，分别静止和全员移动，记录实测拐点/可见人数；不把它与全服1000人目标混为同一结论，不自动分线或隐藏 |
| 集中重连 | 记录断连人数、恢复斜坡、抖动/退避、票据生成、角色恢复及数据库压力 |
| 真实客户端 | 指定硬件/画幅/可见人数，测试姓名牌、动画、插值和聊天同时运行的帧耗时 |

比例、频率、在线人数、活动人数、地图/实例分布和机器人随机种子写入配置并在测试前冻结。服务器为维持产品范围不允许“自动开启无限怪物”：现有单次任务/有限敌人无法无限支撑长时PVE压测，须使用隔离测试角色和足量独立遭遇数据；明确标记测试内容规模，与生产任务完成体验分开。机器人仍经真实协议和业务事务，不伪造胜利或直接修改生产库存。

### 5.2 步骤与统计纪律

按50、200、500、1000逐步增加负载，每阶段记录预热、稳定窗口和失败拐点；先验证M2最小事务链，再进入高并发。完成正常游玩、热点、慢连接、数据库异常和集中重连，不以一张场景截图替代容量数据。

目标混合负载建议稳定至少60分钟，再进行更长时间泄漏观察；时长仅为起始测试建议。固定目标到达速率时记录计划发送、实际发送、服务器接纳、成功、拒绝和超时，不能让机器人因响应变慢而自动降速却宣称吞吐不变。将重试额外流量与原操作成功数分开，报告所有延迟和超时，避免只统计快请求。

## 6. 环境、指标与初始门槛

环境记录包括代码版本/未提交改动标识、协议/schema/规则配置摘要、Rust/Godot/数据库版本、CPU/内存/GPU、系统、网络带宽与RTT、数据库位置与持久化设置、连接池/队列/消息限制、机器人位置和数量、地图实例/可见范围、TLS/代理/压缩配置。

不能只在同机回环上推断公网体验。增加可控延迟、抖动、丢包和限带宽；WSS底层重传会影响交付延迟，应用层同时验证断连及有界重同步，不能假定会收到任意顺序的完整TCP应用消息。

| 指标 | 初始验收建议/记录要求 |
|---|---|
| 在线/认证/恢复 | 人数、失败原因、成功率，连接成功与完成sync.ready分开计时 |
| 普通指令 | 服务端p50/p95/p99，建议p95≤100ms；含服务端排队，不含网络/客户端动画 |
| 持久化指令 | 单独报告含队列、连接池、锁等待和提交的延迟/超时；门槛在部署环境与负载冻结时确定，不能剔除慢事务 |
| 地图tick | 10Hz下耗时与超期率，建议p95<50ms、p99<100ms且无持续积压；实际预算按场景确认 |
| 网络/聊天 | 入出字节、编码字节/实体、公开消息投递量、广播延迟、限流与慢连接断开次数 |
| 队列/内存 | 每层消息数/字节/最长滞留、在途事务、RSS/任务数/连接数，长稳无持续增长趋势 |
| 业务一致性 | 重复扣款/奖励/遭遇消费为零，所有唯一约束和组合快照不变量成立 |
| 客户端渲染 | 目标设备帧耗时p50/p95/p99、可见角色数、绘制/节点/内存；目标帧率在设备和显示范围明确后冻结 |

以上是待在环境/需求冻结后确认的目标，不是已有性能结论。通过入口拒绝大量正常合法请求换取低延迟不算达标；限流拒绝、协议错误、服务故障和结果未知分别报告。热点人数和客户端可见数必须与D01/D02一致。

## 7. 恢复保证范围

网络故障、游戏进程崩溃且数据库持久存储完好时，确认成功的货币/物品/任务/战斗提交必须恢复；普通位置允许在约定实际保存窗口内回退，但不能进入阻挡或错误世界代次。数据库持久化设置与故障模型必须记入报告。

数据库不可用期间不允许无持久化地继续确认经济操作。磁盘损毁、数据库主机丢失和历史备份恢复按D07的RPO/RTO另行验收，不能将“进程重启无丢失”写成“所有灾难零丢失”。演练核对恢复时间点、账本、回执、版本与活动战斗，并记录不可恢复的时间范围。

维护流程验证单写部署、停止新业务、在途事务查明/排空、客户端维护通知、旧规则保留及迁移兼容。每次完整恢复演练使用隔离环境，不覆盖生产数据库。
