# 遇敌提示与战斗准备框

## 运行

仓库根目录执行：

```sh
godot --headless --path client --import
python tests/run_battle_transition.py
LIBGL_ALWAYS_SOFTWARE=1 python tests/run_battle_transition.py --render
```

真实离屏依赖Xvfb，`XVFB_BIN`/`GODOT_BIN`可指定可执行文件。默认截图及逐帧轨迹输出`/tmp/opencode/vssjx-battle-transition`，可用`--output`修改。测试使用独立临时存档，恢复内存角色与保存路径，不访问账号/线上角色或玩家存档。

## 呈现与边界

- 从真实世界交互入口挑战敌人时，先保留地图画面，在角色附近显示白色黑边爆炸框及红色“！”，底部显示金白边框、蓝底青绿分段准备条，参照用户第二张图的视觉层次。
- 红色提示和进度框为程序绘制的像素边框，不声称恢复了未确认的原客户端素材；场景和角色仍复用已有原包图集。
- 条形进度代表实际本地图像、原生角色场景及招式缓存准备，不伪造联网进度。先让出一帧绘制遇敌提示，素材完成占75%、动作缓存占20%，真正准备完成后100%再让出一帧进入战斗；不再每场固定等待0.20＋0.16秒。
- 加载过程中暂停本人移动、个人怪物和场景操作，重复挑战/快捷键不跳过准备，也不扣药、耗蓝、领奖或自动开始回合。加载完成进入原目标战斗，回合仍为0，指令菜单仍收起。
- 本地资源失败或图像异步加载等待超过15秒时明确报错并允许返回探索，不拿假完成替代资源错误；页面切换推进代次，迟到准备不能进入已退出的世界或替换新战斗。

## 验证

- 两张地图分别执行真实遇敌→提示/进度→战斗流程，记录单调且有界的进度、实际缓存结果、角色/怪物静止，以及资源未扣除。
- 原任务前置仍先验证；未接任务不展示加载。提示和进度框在HUD/消息区边界内，覆盖层拦截背景点击。
- 重复挑战、菜单、Escape、攻击不能穿透加载；分别在遇敌提示阶段、实际缓存阶段退出页面，旧准备均不能迟到开启战斗，也不能替换已经创建的新战斗。
- 人为指定不存在的测试纹理，验证失败提示、恢复探索与无资源扣除；测试后立即恢复原目录数据。
- 真实离屏验证进度框像素确实变化，记录两张地图进入战斗后的最终帧；不以headless替代真实截图。

该流程仍是离线PVE呈现；不表示WSS、多人地图或线上战斗已经完成。
