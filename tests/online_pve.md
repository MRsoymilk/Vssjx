# 联网 NPC、怪物与个人试炼

## 阶段一：共享场景实体

青云山道加入清微道人、三只山狼和山灵。定义在`shared/data/qingyun-population-v1.json`，由服务端初始化并推进山狼巡逻，范围限制在出生点两格内，避开地图阻挡；NPC和山灵原地待机。客户端不启动本地世界或读取本地击杀状态。

支持的票据声明`population_version:1`，客户端在世界握手中选择该版本，服务端以独立的`population.state`发送完整有界居民状态；每个世界tick只编码一次，连接复用编码。新上线/重连收到当前状态，后续仅在居民修订变化时发送。玩家同步协议、在线人数和地图哈希保持原约定。

`online_resident.tscn`定义居民节点和姓名标签；原有`AnimatedSprite2D`负责待机/行走，山狼按服务端28像素/秒巡逻插值。小地图显示金色NPC与红色怪物点，玩家人数不包含居民。

阶段一验证：服务端120秒巡逻模拟通过（通行、邻接移动、两格活动范围、统一状态）；Godot协议/场景13项、实际OpenGL截图14项、同屏界面28项、移动控制35项通过。显示与巡逻是第一阶段；在线任务和战斗在下一阶段接入。

## 阶段二：在线任务与持久化战斗

- 票据协商 `pve_version:1` 后，通过认证世界连接接收私有 `pve.state`，发送严格的 `pve.command`，接收 `pve.result`。旧客户端无需启用此扩展。
- 清微道人提供“山林试炼”、恢复元气和一次性任务奖励；三只不同山狼分别计数，山灵提供额外遭遇战。各角色独立记录击败状态，同屏巡逻实体保持共享。
- 服务端校验会话、角色所有权、站立状态、目标距离和回合版本；客户端不能上报伤害、奖励或生命值。战斗中禁止移动。
- 角色进度、药品、战斗和操作回执在同一 PostgreSQL 事务中提交。相同操作 UUID 重试返回原回执；更改内容会冲突。断线和进程重启都能恢复未结束的战斗。
- `tests/run_online_pve.py` 使用隔离数据库验证三狼试炼与领奖、逐回合战斗、重复操作、旧回合拒绝、药品事务失败回滚、恢复、进程重启、角色隔离和连接接管。
- 规则测试覆盖绝技条件、满血用药、凝神、撤退、胜负与30回合上限。当前在线地图为青云山道，未扩展离线后续地图剧情。
- 可使用 Docker PostgreSQL，或显式配置 `SSJX_TEST_PG_BIN` 与 `SSJX_TEST_PG_WORK_DIR` 启用测试专用便携 PostgreSQL；只清理自身创建且位于已核验测试目录下的临时集群。可用 `SSJX_TEST_SERVER_BIN` 指定独立构建的测试服务端。

## 阶段三：客户端任务与参考战斗界面

- `online_encounter.tscn` 提供道人接取/交付/恢复和怪物挑战。选择行动后先沿权威地图靠近，等待站稳及移动确认后再提交交互。
- `online_battle_view.tscn` 复用既有 `battle_hud.tscn` 与 `battle_inspect.tscn`；按用户参考保留右侧人物、左侧怪物、蓝色脚圈、原指针、黄纸竖向六项菜单和上下布局。六项依次为“攻击、技能、待机、道具、查看、逃跑”，技能/道具各有选择面板。战斗期间隐藏地图工具栏，底部原公共聊天区域继续收发消息与表情。
- 0键切换自动攻击；绿色选择倒计时到零会提交待机请求。按最新参考要求移除F加速与扳手按钮。回合结果仍由服务端判定，客户端不能修改伤害或奖励。
- `OnlinePve` 验证私有快照，按角色状态版本拒绝旧回执回滚当前进度；未确认的操作只保存在账号内存中，重新入场后用相同UUID和内容重试。退出登录清除该内存状态。服务端战斗与已提交结果不依赖客户端内存保存。
- 已击败的怪物仅从本人地图与小地图隐藏，其他角色仍能进行自己的试炼。人物属性、进度与药品来自服务器，不写入单机存档。
- Godot `online_pve_test.tscn`：28项检查通过；实际渲染另验证截图。`online_pve_live_test.tscn`：13项真实 Rust/PostgreSQL 联调检查通过，包含界面自动接任务、追近巡逻怪物、战斗操作、战斗中聊天、丢失响应重试与重连恢复。
- 现有共享界面28项、移动控制35项、公共聊天48项、世界增量50项、人口显示13项均通过；Rust全量43项测试与Clippy通过。
- `SSJX_TEST_PVE_GODOT=1` 可随完整服务端集成测试运行真实客户端；`SSJX_TEST_PVE_CLIENT_ONLY=1` 只运行隔离数据库下的客户端联调。`GODOT_BIN` 需指向Godot控制台程序，`SSJX_PVE_CAPTURE_PATH` 可配置界面测试截图目录。
- 部署新服务端后，启动时自动运行0006数据库迁移。现有运行中的旧服务端未被测试流程停止或覆盖。
