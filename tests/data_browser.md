独立场景：`client/scenes/admin/data_browser.tscn`。数据适配器位于 `client/scripts/admin/data_catalog.gd`，不经过登录、玩家创建或世界模拟。

## 独立桌面工具布局

```sh
python tests/run_admin_scene_layout.py
python tests/run_admin_scene_layout.py --render --output /tmp/opencode/vssjx-admin-desktop-960
```

真实渲染需要Xvfb；可按`tests/testing.md`设置`XVFB_BIN`和Mesa环境变量。测试只使用独立用户数据目录，不读写玩家存档，也不连接账号服务。

- 两页和总图弹窗统一使用960×540的默认物理窗口及逻辑画布，不继承游戏的手机分辨率。较大窗口按原像素扩展布局；仅在桌面可用区域不足时才缩小整个桌面画布。
- 管理页按960×540重新调整三栏宽度、间距、字体与预览高度；预览随窗口高度增长。世界总图采用地图与说明左右布局，不再使用竖长弹窗。两个场景在编辑器中的根Control最小尺寸也明确为960×540。
- 编辑器中先关闭Embed Game on Play，再按F6；工具不提供嵌入游戏视口的适配逻辑。
- `world_overview.tscn`现在是可直接F6的完整Control内容，自动加载79个地点与78条连线。管理页使用`world_overview_popup.tscn`包裹同一内容，并传入当前选中的目录条目，原生弹窗按桌面可用区域限制大小。
- 两者仅改变当前管理窗口的缩放参数，游戏工程仍使用320×480，不修改项目设置或存档。窗口小于桌面布局时会缩小显示，放大独立窗口即可提高可读性；管理页的总图弹窗也是独立原生窗口。
- 回归首先断言两页初次启动的窗口与逻辑画布都恰为960×540，再覆盖1280×720、1360×900和不足桌面尺寸时的缩放兜底。检查八个分类、地图目录、详情、复制按钮、底部说明、全部总图地点的边界，以及管理页弹出的地图是否完整保留。
- `--render`分别以独立进程启动两个管理工具，检查专用窗口标题、原生子窗口策略及实际渲染；不创建游戏内嵌入宿主。

修复前布局回归20项中10项失败，复现小窗口裁切、弹窗越界及世界总图缺少独立运行入口。修复后的执行记录与截图在输出目录的`report.json`、各测试日志和PNG中，运行命令不会覆盖私有配置或修改分析资料。

## 数据边界

- 武器、物品、人物基础属性、任务文本：在不加入场景树的独立状态对象上读取现有规则，不调用自动加载的 Game 的新建、恢复、加载或保存方法。
- 原包物品从 `client/assets/data/original_items.json` 读取，使用 `tools/import_item_catalog.py` 从原包目录与解码清单完整导出。共 208 件：56 武器、81 装备、71 其他；所有图标逐字节复制至客户端，不重新绘制。按 iw/if/ix 文件名前缀分类，明确不将该前缀当作完整的原服物品类型表。
- 原版名称、物品ID映射、等级、装备槽位与属性尚未恢复，保留 null，并在界面显示“—”。管理页按原始资源编号展示全部图标，不因为业务逻辑尚未接入而隐藏。
- 本地武器规则青锋剑、消耗品规则回春散仍独立显示，状态为“已接入”；不将重建版名称或数值冒充原包定义。装备槽位直接使用背包中的十个定义，九个未接入装备规则的槽位标为“预留”。
- 分类索引共753条，包含跨分类引用：武器57、装备91、物品210、人物6、任务/线索16、地图217、怪物123、素材/动画33。怪物由6条重建定义和117份原包动画组成；总索引数不等于独立物品、怪物种类、任务或可游玩地图数量。

- 地图217条包括214条已审核的Online原包目录及3条已接入场景定义；原包目录保留同名记录。世界总图已恢复79个位置与78条线段，可展开、悬停查看地点类型与等级；135条隐藏位置保持未知。场景地形未取得时明确提示，不生成猜测地形。原包编号不等同于重建服务器ID，总图连线不当作完整传送配置。来源索引为 `analysis/catalogs/online_world.json` 及其客户端副本，证据及候选格式见 `analysis/recovery/maps/README.md`。
- 任务/线索16条包括5个重建阶段、1组任务界面文案、10组引导文案/线索（teach.str及teach1～teach9）。界面单列原版任务总数未知，不能把16或5当作原版任务数量。文字仅在字段、JSON与文本摘录中展示，不作为指令执行。
- 离线地图调用原有 `_build_map()`，仅生成地形与阻挡，不调用 `_ready()` 或添加到场景树；不模拟角色、NPC、怪物及树木。其阻挡预览明确只表示地形。
- 联机地图直接读取客户端 JSON，显示文件中的 tiles/blocked 与出生点；不连接在线数据库，也不显示在线账号背包或角色实例。
- 动画、特效、地图装饰等从演员索引和分片读取。动画预览不修改全局 SpriteFrames 的循环属性。
- 刷新重新读取 JSON 和定义列表。修改 GDScript 常量后需重新运行场景，管理页不是热重载编辑器。
- 玩家状态、密钥与代理配置不属于数据浏览范围。管理页没有写入或删除操作。
