# APK 账号网络诊断（2026-10-17）

用户反馈朋友在 APK 登陆时只显示“网络请求未确认”，而朋友用同网络浏览器打开 `/api/v1/server-info` 可以看到正常 JSON。浏览器可达不等于 APK 网络请求成功，不能直接断言必须使用代理或服务器故障。

本机诊断：

- 本机网页代理、游戏服务和数据库健康，cloudflared 有四条就绪连接。
- 独立 Edge 浏览器禁用浏览器代理后，公网首页及状态接口返回 200，虚构不存在账号的登陆返回 JSON 401。
- Godot 4.7.2 桌面原生 HTTPRequest 对公网状态接口返回 200，空对象登陆请求返回 JSON 400（约 1.5 / 2.1 秒）。未发送真实玩家凭据。
- Python urllib 请求会收到 Cloudflare 403 / 1010，而上述浏览器和原生 Godot 请求正常；这不能证明朋友的 APK 同样被 Cloudflare 拦截。没有更改 Cloudflare 安全配置。
- 未取得朋友 APK 的原始 HTTPRequest 结果，因此实际失败原因尚不能确认，也没有在朋友的网络或 ARM64 真机上完成验证。

客户端修改：

- 账号请求超时从 8 秒放宽至 30 秒，兼容较慢公网链路；这是缓解措施，不将慢网络当作已确认根因。
- 区分 DNS、TLS、无法连接、超时、传输中断、无响应和过大响应；其他结果显示数值错误码。
- 网关返回非 JSON 或响应超限时，保留安全的 HTTP 错误状态，区分 403 与 5xx。状态文字不展示响应正文、密码、令牌、Cookie 或私有头。
- 原有 JSON 业务错误（密码错误、密码长度、会话失效、限流等）仍按业务代码显示。注册及登陆不自动重放，避免未知结果下重复创建或切换会话。

验证：`login_ui_test.tscn` 59 项通过；`python -X utf8 tests/run_account_network_timeout.py` 使用独立回环 HTTP 服务，在 9.2 秒后返回 JSON 401，确认超过旧 8 秒窗口后仍正常进入账号错误处理，且只有一次请求（3 项通过）。`tests/run_account_auth.py` 的独立 PostgreSQL/Rust/UI 验证通过，账号 UI 19 项。测试不访问玩家数据库或保存玩家凭据。
