# 行走路线和移动控制修正

本轮针对单人和多人都感觉“走得很乱”的反馈，记录到以下实际问题：

- 本地四方向移动使用默认欧氏估价，`(16,17) → (23,23)` 的空地最短路线在横向和纵向之间频繁切换。改为曼哈顿估价后，相同13格路线只转一次弯，仍绕开河流和树木。
- 本地点击向右后按住左键，原长路线仍优先执行。现在按键接管后续路线与交互意图，完成当前半格后按新方向移动，不回拉或跨格。
- 本地菜单、背包、人物、交互和战斗暂停曾将人物拉回旧格中心。暂停现在保留实际位置与尚未完成的一步，清掉旧的长路线；恢复只完成该步。显式复位的 `stop_moving()` 保留格中心对齐语义。
- 多人显示曾以100像素/秒追赶每100ms收到的72像素/秒权威坐标，造成提前追到后插入idle，拐弯时还会走斜线。`OnlineActorMotion` 保留收到的格边拐点，通常以72像素/秒消耗路线；持续移动时不会因两包之间暂时没有距离而切换idle。真正积压时最多以1.5倍速度沿原路线追赶；发布缺口使用共享通行网格恢复，队列有上限，所有显示均不写回权威位置。
- 多人100ms限频曾直接丢掉快速改目标或停止指令。现在只保存最新一条未发意图，窗口打开后补发，并在离开/断线时清除。松键立即排队停止；点击移动会清除旧键盘停止标志，避免新点击被上一轮松键覆盖。点击水面、树木或地图外会停止旧路线，而非继续执行旧目标。

仍使用原 `AnimatedSprite2D`、原待机/行走帧和四方向通行约束，没有修改服务端位置规则、地图哈希、账号或存档格式。

## 验证

```sh
godot --headless --path client res://tests/movement_control_test.tscn
godot --headless --path client res://tests/motion_regression.tscn
godot --headless --path client res://tests/click_motion_regression.tscn
godot --headless --path client res://tests/test_runner.tscn
```

新增用例验证空地少转弯、反向按键接管、半格暂停与恢复、多人保留拐点、15/30/60/120 FPS下100ms发布持续走路不插入idle且正常速度一致、停下后恢复动画idle、树木绕行、键盘切鼠标和点击障碍停止。

同一用例还在 `127.0.0.1` 随机端口启动真实TCP/WebSocket连接，检查第一条移动、快速替换后的最终目标和停止指令确实通过套接字发送，并且序号连续、断线后清除旧意图。它不连接生产服务，不涉及真实数据库或认证世界联调；完整双客户端服务端验证仍需Docker PostgreSQL的 `tests/run_shared_world.py`。

设置 `SSJX_CONTROL_CAPTURE_PATH` 为已存在目录，可用真实渲染运行新增用例；既有 `motion_smoke.tscn` 可通过 `SSJX_MOTION_PATH` 录制72帧原地待机、向右、向左、停下的真实引擎画面。
