# Vssjx 联机版设计

状态：设计草案，尚未实施。本文档不表示服务器、联网功能或1000人容量已经实现。

## 已确认的产品范围

- 联网目标为多人同地图，而不是仅上传本地存档。
- 首版支持账号进入服务器、共享地图、独立PVE战斗、个人任务怪和公共频道聊天。
- 后续部署到公网，暂定1000人同时在线的容量目标。
- 服务端技术方案采用Rust，客户端继续使用Godot。
- 当前工作仅整理设计，不迁移现有工程，不创建服务端代码。

## 首版边界

首版沿用现有两张地图及离线任务链，优先完成以下流程：

```text
注册/登录 → 创建或选择角色 → 进入共享地图 → 移动/公共聊天
    → 与个人任务目标交互 → 独立PVE → 领取奖励 → 保存与重新登录
```

暂不建设交易、组队、帮会、PVP、共享Boss、跨服、支付及完整运营后台。基础管理能力仍需要禁言、封禁、日志查询和备份恢复。

原版服务器和战斗公式没有恢复。联机服务基于当前原型的重新编写规则建设，不宣称还原原版服务端。

## 尚待确认的事项

| 事项 | 当前建议，不视为已确认需求 |
|---|---|
| 1000人口径 | 按全服同时在线设计；是否必须支持1000人同一地图实例并互相可见，需要确认 |
| 地图分线 | 预留实例标识，但不擅自以分线替代“同地图互见”；不同实例的玩家不可见 |
| 同屏人数 | 不默认裁剪或隐藏远处以外的可见玩家；若需人数上限，应单独确认 |
| 账号角色数量 | 建议首版每账号一个角色，同时只允许一个有效游戏会话 |
| 重复登录 | 建议明确提示并拒绝第二次角色上线，后续可增加显式顶号 |
| 战斗断线 | 建议保留短暂重连窗口；超时如何结束、扣除和结算，需要确定具体规则 |
| 离线模式 | 建议保留现有离线存档入口，与线上角色严格隔离 |
| 聊天记录 | 建议仅向客户端提供有限近期记录；服务端审计保留期另行确定 |
| 部署环境 | 需要确认CPU、内存、带宽、地域和预算，之后才能确定部署规格 |

所有文档中的频率、限额和延迟数值均为起始建议，需配置化并通过实测确认。
