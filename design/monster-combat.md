# 怪物遭遇与强力招式 V1

新增玩法设计，沿用现有像素角色、战斗面板、伤害数字与暴击屏闪。共享参数为 `shared/data/monster-combat-v1.json`，Godot 镜像由 `tools/sync_balance_data.py` 同步。

强力怪判定为首领、守卫、精英或10级以上怪物。每次行动25%疾风连击（两击各70%）、20%横扫千军（每名存活目标80%）、20%撕裂重击（110%并施加流血），其余普通攻击。封印阻止横扫；睡眠阻止整个行动。每次伤害独立命中、暴击与反伤，击杀或反伤死亡后停止余下攻击，不攻击尸体。普通怪暴击率8%，强力怪15%，倍率150%；防御指令和护体继续生效。

流血按命中后伤害的20%生成，每个完整回合末扣血一次，持续3次；同一角色受到重复撕裂时刷新时间并保留较高伤害，不无限叠加，不对死亡角色扣血或复活。状态与事件随战斗JSON保存，重连不重抽。招式名称、逐击数字和流血提示在现有阵列视图显示，群攻合并动作、连击保留独立动作；全部技能特效结束后再播放下一行动。

新单人／组队阵列冻结 `monster_revision=1`；旧JSON缺字段为0，保留普通单击与旧暴击规则。本地和联机已接入，不改变玩家的技能数值。未部署或打包。

单人遭遇抽取1／2／3只的概率为60%／28%／12%。保留所选主怪，从同地图、等级差不超过3级、未刷新冷却的非NPC普通怪中优先抽取不同增援；模板不足时允许同种普通怪作为独立槽位增援，保证仅有一种普通怪的扩展地图也能出现2～3只。不得复制首领；只有首领且无普通怪可增援时保留单怪。只有击败整场全部敌人才领取每只怪的铜钱和修为，任务进度及刷新状态按居民ID去重，撤退／失败不领取部分击杀奖励。首领含增援的总气血仍采用既有单人预算，本地／服务端一致。

联机仍走单人PVE事务、原操作编号、战斗ID和修订号；V1客户端以 `challenge.encounter_version=1` 显式启用阵列（新增精英能力见下文V2），`enemy_slot` 指定敌人槽位，原 `target` 继续表示技能ID。旧客户端不发送新能力时保留旧单怪入口，旧在途战斗继续旧规则，避免隐藏的增援攻击旧界面。阵容、独立状态、完整回合流血与命中事件存入现有战斗JSON，无新增数据库字段。重连不重新抽取，不重算伤害，重复操作不重复奖励。

本地与联机复用现有阵列视图，保持原生像素资源、六指令、逐击伤害数字、暴击屏闪及死亡动画。每只敌人独立血条、点击选敌；被击败后自动选取下一存活目标。技能全部特效结束再播放下一行动；多目标施法只播放一次音效。底部“战斗指令”和“自动战斗”同一行居中，各72×22逻辑像素；开启后文字为“手动战斗”，按钮不显示快捷键前缀。本地自动模式保留低血量用药及可用技能选择。

验证命令与结果见 [单人多怪回归](../tests/solo_encounters.md)。构建使用独立输出目录，未停止运行中的本地服务。


## 同图连续挑战触发精英（2026-10-21）

同一角色在**同一地图连续挑战同种怪物5场**，第五场所选主怪成为精英。计数依据接受的遭遇请求，排除战斗内的攻击次数和回合数；居民ID不同、地图内走动都不清零。同种由服务端居民定义的 `art` 标识确定，因此三处山狼共享种类计数。实际切图或挑战另一种怪物重新计数；对话、恢复资源、重新登录不清零。达到5后计数保持5，撤退和战败继续触发，整场精英胜利才清除并开始下一轮。不额外复制精英，不改变任务、居民刷新、金币和经验的归属规则，复活不重复奖励。

角色级计数保存在 `characters.hunt_pressure`（迁移0028，JSON对象，map/species/count，范围0～5）；迁移只新增字段与切图重置触发器，默认空对象，保留已有角色数据。实际切图即清零，离开后返回同图也不会延续旧计数。单人事务将计数、战斗、资源、操作回执一起提交，组队仅对实际在线参战者更新，由现有角色锁、业务保存点、操作回执保证不重计和失败回滚。任一参战成员达到5触发本场精英；离线、暂离和未参战成员不会触发或累加。精英获胜时仅清除达到5且地图、种类匹配的成员计数。

| 能力 | 单人精英 | 2～5人参战精英 |
| --- | --- | --- |
| 主怪气血 | 原预算×2 | 原预算×2.5；非首领另乘1+0.25×额外人数 |
| 攻击／防御 | ×1.4／×1.2 | ×1.7／×1.3 |
| 连击概率／次数 | 60%／3击，每击65% | 65%／4击，每击65% |
| 其他攻击 | 横扫，单人目标 | 横扫所有存活成员 |
| 暴击 | 每次命中35%，伤害175% | 每次命中45%，伤害200% |
| 流血 | 每次造成正伤害可施加；20%，3次回合末 | 相同，刷新时长并保留较高伤害 |
| 妖躯复生 | 最多1次，每次恢复50%气血 | 最多2次，每次恢复60%气血 |

普通首领／组队预算先结算一次，再强化主怪。怪物原等级、种类、图像、任务ID和奖励保留，数值上限100000。每次攻击独立命中和暴击，睡眠、防御、护盾、反伤继续有效；封印会阻止横扫群攻及法术。直接伤害、反伤或持续伤害致死均检查有限复活；队伍全灭时直接失败。复活清除怪物持续伤害和控制，恢复怪物灵力，不恢复玩家，不重置次数。剩余复活次数、流血和逐击事件随战斗JSON冻结，重连不重抽。

新增精英阵列 `monster_revision=2`，主怪附 `elite={party_size,revives_left}`，复活事件为 `action=revive,skill=monster_rebirth`。客户端挑战发送 `encounter_version=2`（单人、组队）。旧客户端仍可展示旧战斗和前四场普通遭遇，达到精英条件后拒绝创建并提示更新，避免通过不声明渲染能力绕开玩法。新增字段为空时不改旧组队请求摘要，既有回执保持可重放。

本地实际遇敌也在进入战斗前确认存档，保存失败则回滚计数并停止进入；旧存档缺字段时按空计数兼容，无需删除存档。本地测试直接构造战斗不会累加玩家计数。真实入口使用现有阵列面板，顶部显示“精英遭遇”，名字前缀“精英·”，查看面板显示剩余复活。复活等待完整原生死亡动画，移除墓碑，恢复角色并显示绿色数值和“妖躯复生”；伤害、暴击和屏闪沿用原表现资源。

这是增加重复刷怪的战斗压力，不作脚本身份判定，也不封禁账号。更换地图或怪物种类是明确允许的重置条件，因此不能单独替代完整的脚本检测。验证见 [精英遭遇回归](../tests/elite_hunt.md)。


## 阵列血条定位修正（2026-10-21）

换装角色攻击帧会恢复原始头／身体的横向位移，显示位置可能明显偏离精灵节点原点。阵列视图的姓名、气血条、灵力条和点击区域统一使用当前帧实际贴图偏移相对原图原点的差值，再经演员画布变换转换到UI坐标；不再直接使用精灵节点的局部位置。血条／文字保持正向，支持左右镜像及演员层缩放。选中标记采用同一个显示定位点。首次展示、攻击每帧、特效尾段等待、取消和自然回位均同步，不改变人物动作轨迹、属性或伤害规则。适用于共用阵列视图的本地、联机单人和组队战斗。

`battle_hud_anchor_test.tscn` 使用实际换装角色逐帧检查左右攻击、归位、取消、不同层变换和特效尾段；54项通过，并检查实际OpenGL攻击截图。组队回合54项、单人遭遇55项、精英与复活22项回归通过。没有执行打包或部署。
