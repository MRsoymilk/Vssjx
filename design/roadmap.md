# 实施路线

状态：待执行计划，以下工程与服务端工作均尚未开始。前置范围见[设计入口](README.md)。各阶段测试与容量验收统一记录于[tests/online_test_plan.md](../tests/online_test_plan.md)。

## 1. 执行原则

- 先完成可验证的纵向流程，再扩展容量，不同时重写全部界面。
- 首版最终交付同时包含多人地图、公共聊天、个人任务和独立PVE；阶段交付不等于完整首版。
- 不因“1000人”提前引入微服务；不以连接数替代实际玩法容量。
- 本轮仅写设计文档，以下工程与服务端工作均尚未开始。

## 2. 阶段划分

### M0：目录、配置与契约

工作：

- 确认1000人是全服容量还是单地图实例容量，是否允许分线。
- 迁移Godot工程到`client/`，建立`server/`、`shared/`和`deploy/`。
- 调整`vmanage`扫描与启动逻辑，保留游戏ID和游玩统计关联。
- 调整启动脚本、资源转换与Godot UID关联路径，配套工具按新目录适配。
- 提取权威地图阻挡、怪物、任务、物品和战斗配置。
- 定义版本化协议；冻结首轮接口的消息范围。

### M1：服务骨架与账号角色

工作：Rust/Axum/Tokio启动、配置、健康检查、结构化日志、PostgreSQL迁移、账号密码、会话、角色创建/查询、WSS认证。

### M2：多人进入同一地图

工作：地图实例、角色进入/离开、输入序号、权威移动、阻挡与速度校验、可见范围、插值、心跳、重连、会话代次与重复上线策略。

### M3：公共聊天

工作：公共频道界面、跨地图广播、发送者身份校验、长度与频率限制、去重、有限历史、禁言、慢连接保护。

### M4：个人任务、背包与PVE

工作：权威属性与背包、事务性购买/用药/装备/丢弃、个人任务怪、任务交互、服务端回合规则、事件动画、战斗重连与奖励幂等。

### M5：公网部署与容量

工作：TLS/WSS、反向代理、私网数据库、指标、基本管理能力、备份恢复、优雅停机与部署规格调整。

## 3. 风险与发布前决策

| 风险 | 对策 |
|---|---|
| 32×32地图人群拥挤，AOI退化为近全图广播 | 确认是否允许分线、扩图或其他显示策略 |
| 客户端同时保留本地规则和在线规则导致双重结算 | 在线入口只展示服务端结果，离线模式使用独立适配与存档 |
| 客户端动画阶段被误当作服务端事务阶段 | 权威计算与动画播放解耦，结果先可靠保存 |
| 网络重试、事务成功但响应丢失 | 持久化操作回执，稳定幂等键，唯一奖励约束 |
| 战斗和背包并发修改同一库存 | 同角色串行化、状态版本、事务约束 |
| 数据库或慢连接拖住地图任务 | 有界通道、异步持久化协调、背压与故障降级 |
| Rust异步共享状态过度复杂 | 明确状态所有者，避免全局大锁，先采用单进程方案 |
| 公网刷屏、撞库、连接滥用 | 分层限流、鉴权、禁言封禁、审计与基础防护 |

开始工程迁移前确认容量与分线口径；开始账号模块前确认角色数量和重复登录策略；开始PVE前确认断线超时规则；公网发布前确认部署预算、监控、数据备份与聊天审计保留期。
