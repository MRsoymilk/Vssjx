# 胜负动画与战斗结束

原始素材是 `analysis/unpacked/ssjx/ltz_win.ani`、`ltz_win.imgs` 与 `ltz_lose.ani`、`ltz_lose.imgs`。各只有一幅原始字图，通过 ANI 两个不同偏移的合成帧形成抖动；序列两个步骤均为2 tick。游戏导入保留原图、层偏移、反序帧索引和步长，生成 `main/ltz_win`、`main/ltz_lose`，由同一个 `BattleResultView` 播放。

用户给的视频 `冒泡蜀山剑侠.mp4` 约66～75秒可见多次普通战斗：最后一击后回到地图，消息栏保留“战斗结束，你获得了胜利”及奖励，不要求点击独立结算弹窗。视频当前片段未确认这两个 `ltz_` 图标在普通战斗中的具体锚点和停留时间；本次按用户要求复用胜负素材，显示于战场上半部，停留1.6秒后自动返回。这个锚点、10 tick/s时钟和停留时长是适配值，不标注为原版实测。

流程统一为：最后一击 → 原包死亡/墓碑动画完整结束 → 结算确认 → 胜利或失败字图 → 自动返回当前地图；撤退显示撤退文字，不冒充失败。取消原有“返回山道”结算按钮和额外任务说明弹窗。奖励、恢复位置和存档仍由现有本地规则/服务端决定，界面不新增发奖或写数据库操作。

本地等待原有保存完成后开始结果播放；保存未确认时保留提示，暂停自动返回，避免错误一闪而过。结果保存在本地系统消息中。联网消息继续使用服务端回执，断线暂停自动返回；重复快照不重置结果计时，新战斗才清理。图标出现前0.4秒屏蔽残留点击。

技能选择证据见 [技能界面](../skills/interface.md)；六行纸框与独立说明条由 `SkillPicker` 为本地、联网及旧能力服务器共用。

验证：`client/tests/battle_result_test.tscn` 检查胜败素材、原序列时长、重复结算、自动返回、断线暂停及技能选择输入；`battle_death_test.tscn` 保留完整死亡动画顺序；`skill_battle_test.tscn` 验证具名技能回合与服务端指令；`online_pve_test.tscn` 验证旧能力兼容。
