# 地图与点位管理

入口：独立本机管理监听器的 `/maps`（例如配置为9091时为 `http://127.0.0.1:9091/maps`）。公网游戏监听器不挂载页面、脚本或管理API。本轮仅改源码和测试，没有更新正在运行的服务。

## 范围

- 搜索216张现有地图，查看只读32×32导航网格；支持点击网格填写点位坐标。
- 地图：允许新进入、出生点、驿站位置与开放状态。禁入阻止跨图传送、神行符和入派旅行，但已有角色仍可登录、停留和离开，不迁移玩家。
- 刷怪／NPC：现有点位的坐标、启用状态；怪物个人刷新间隔1～86400秒。保留既有任务和角色ID，不提供新增地图、美术、怪物数值、任意脚本或SQL编辑。
- 传送：现有入口的启用、名称、主格／多格触发范围、目标地图及可选到达坐标；空到达坐标使用目标出生点。原有任务门槛保留。驿站目的地选择与触发入口可分别关闭。
- 采矿／采药：现有418个采集点的启用、坐标、四种材料、时长、数量范围和刷新间隔；不新增材料资产。

## 草稿、发布与生效

迁移 `0036_map_management.sql` 增加草稿、不可经API修改的发布记录、活动版本指针和操作回执。默认版本0来自打包目录，不修改静态地图文件或资源哈希。

1. 保存草稿不会生效。草稿使用乐观修订号，两个编辑器不能静默互相覆盖。
2. 校验类型、既有ID、地图存在性、可行走／可达坐标、刷新与产量边界、触发格重叠和到达格传送冲突。错误显示在页面，发布端再次校验。
3. 发布版本、更新活动指针与采集配置、更新草稿基准、写审计和回执在同一事务。UUID重试仅回放原回执，不重新激活旧版本。
4. 本进程发布成功后更新运行快照，点位在下一次世界刷新应用；NPC／怪物位置切换使用新姿态基线，不把重定位误画成穿越场景的行走。进行中的战斗仍使用原战斗实例；新击败使用新刷新间隔，已产生的冷却截止时间不改写。正在采集的材料、产量和刷新时长仍按开始时的冻结参数结算。
5. 发布历史最近30条可恢复到草稿，版本0恢复初始配置；恢复本身不生效，必须再次校验和发布。

页面提交过程中锁定编辑，未知网络结果可用相同操作UUID重试，避免重复发布。管理写入沿用本机来源、Host、Origin和随机操作员令牌校验；要求填写审计原因。当前实时缓存面向既有单个游戏服务进程；多实例共享数据库时须同步更新／重启其他实例，不能假定其他进程的点位缓存会自动热更新。

## 客户端兼容

- 票据新增 `map_rules_version=1` 能力；联机握手及更新携带当前地图的独立运行配置。联机入口查找、绘制、自动传送与靠近操作使用该配置，离线 `SharedWorldMap` 不变。
- 继续校验地形哈希、AI目录哈希和怪物身份／模型／战斗数值，没有关闭资产校验。怪物刷新截止时间仍受1天上界约束。
- 没有发布配置时旧客户端保持原行为；已发布地图对没有能力协商的客户端明确返回 `MAP_UPDATE_REQUIRED`，避免错画入口。进行中的旧连接遇到发布也提示更新，已保存战斗不丢失。
- 使用功能需更新客户端与服务端并应用0036（采集还需0035）。未推送、打包、部署或迁移现有数据库。

## 验证

```sh
GODOT_BIN=godot SSJX_TEST_SERVER_BIN=/path/to/vssjx-server python tests/run_map_management.py
godot --headless --path client res://tests/map_rules_test.tscn
```

`PLAYWRIGHT_MODULE_PATH`、`PLAYWRIGHT_CHROMIUM_EXECUTABLE`存在时，专项脚本同时运行真实Chromium管理页面；可用 `SSJX_MAP_CAPTURE` 指定页面截图。仅使用独立临时PostgreSQL与自行创建的测试账号。

覆盖权限与公网隔离、非法坐标／ID／传送目标、并发草稿、发布回执故障整笔回滚、重试及重启后重试、实际NPC迁移与怪物停用、进行中的战斗与采集不被改写、90秒刷新、地图禁入和已有玩家重连、新传送目标与出生点、历史恢复、持久化、旧客户端提示及真实Godot自动传送。页面专项另覆盖搜索、网格错误提示、提交时锁定编辑和草稿／发布／恢复全流程。

最终验证：地图服务端89项、真实Godot联机11项、Chromium页面13项、客户端规则／OpenGL14项、Rust177项通过。回归通过：安全管理98项／浏览器38项、组队131项／客户端12项、采集28项／客户端15项、AI世界真实客户端25项及服务端完整链路。

额外运行旧 `run_online_maps.py` 时，在第191行妖王战斗必须胜利的断言失败，未计入通过；该脚本同时承担旧战斗数值场景，不等同于地图管理专项。当前新增专项已独立验证传送、禁入、到达点、运行中战斗保留与重启持久化。未为绕过旧战斗断言修改角色或怪物数值。
