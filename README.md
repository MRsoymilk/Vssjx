# 蜀山剑侠 · 归来

基于 `analysis/` 中原始《蜀山剑侠Online》320×480 客户端素材，用 **Godot 4.7** 编写的离线可玩原型。

工程已划分为`client/`（Godot客户端）和`server/`（Rust服务端）。已开放独立的线上账号/角色、青云山道多人同图移动和公共聊天；当前功能千人短测已通过，任务/PVE、完整混合负载与公网长稳仍未验收，详见[容量记录](tests/capacity_delta.md)。联机进展见[design/README.md](design/README.md)。

## 启动

- 使用 Godot 4.7 打开 `client/project.godot`，按 **F5** 运行项目。
- 命令行在仓库根目录运行：`godot --path client`。
- 服务端启动：`cargo run --locked --manifest-path server/Cargo.toml`，默认监听`127.0.0.1:8080`，详见[server/README.md](server/README.md)。
- 本机服务监控与用户管理：启动后打开`http://127.0.0.1:9090/`，服务概况、用户管理、操作审计、全局通知分别成页，以面包屑导航；支持按角色名定位并管理其所属账号。远程管理使用SSH隧道。配置与安全边界见[日志与监控](server/README.md#日志web-监控与全局通知)、[防作弊与用户管理](tests/security_admin.md)。

服务端部署参数读取根目录`.env`，参考[.env.sample.txt](.env.sample.txt)填写；`.env`不会提交Git。默认数据库URL为空，仅运行连接检查，启用账号前需配置数据库。客户端不读取服务端秘密配置。

多平台接入已从P1开始：`client/scripts/interface/`提供平台入口和原生配置、存储、显示、生命周期及资源准备边界；战斗加载已改经资源接口处理进度、取消和失败，保留现有规则、存档格式及游戏画布。Web导出、手机浏览器及其他接口仍按[平台方案](design/platform_interface.md)推进，当前不是网页版交付。

已生成所需 Godot 素材，离线试玩不依赖Python或联网；Godot首次打开客户端时导入素材。本项目采用OpenGL Compatibility渲染器。

商城已覆盖全部 208 个已恢复原包物品图标，并保留六个兼容物品；按原包两列结构、四页签及物品类别浏览，支持十个装备槽和不同药品。显示名、售价、属性及部分换装对应仍属重建规则，原始证据与实现边界见[商城与物品说明](design/shop_catalog.md)。

联机 PK：点击同地图玩家，在资料页选择“邀请决斗”；对方在左侧提示中确认后开始回合制切磋。拒绝后，邀请者需等待 5 分钟才能再次邀请该角色，冷却由服务端持久化校验。切磋不消耗常规血蓝与物品、无奖励；规则与验证见[玩家决斗](design/player-duels.md)。需更新客户端和服务端后启用。

联机社交：点击地图中的玩家或按完整角色名查找，可查看公开属性、外观、十个装备槽及帮派。菜单“社交”管理好友与双向申请，“帮会”支持创建、申请/审批、公告、成员管理、移交、退帮和解散。关系按角色持久化，所有权限由服务端校验；需更新客户端和服务端并应用数据库迁移，详见[玩家资料、好友与帮派](design/social.md)。

联机组队：玩家资料中“邀请组队”，对方在左侧提示中同意；菜单“队伍”查看成员、准备、移交、移出或退出。2–5 人同图集合、全员准备后由队长靠近怪物发起共享战斗，支持 2–5 个独立敌人、群攻和群体辅助。怪物数值按人数增强，奖励与任务由服务器统一结算；数值属于重建规则，见[组队与多怪战斗](design/teams.md)。

## 项目数据管理

使用 Godot 4.7 打开 `client/scenes/admin/data_browser.tscn`，按 **F6** 单独运行；或在仓库根目录运行：

```sh
godot --path client res://scenes/admin/data_browser.tscn
```

Windows 也可运行 `./tools/open-data-browser.ps1 -GodotBin "你的Godot可执行文件路径"`，支持 `GODOT_BIN` 环境变量或 PATH 中的 `godot` / `godot4`。

管理页提供武器、人物装备、物品、人物、任务、地图、怪物、特效、素材/动画、原包归档十类目录，可搜索名称、ID 和属性，按状态筛选，查看字段、JSON 数据和定义来源；人物和特效支持动画预览，地图支持地形与阻挡预览。**只读浏览项目定义与原包资源**，不连接数据库或读取玩家存档。按 F5 刷新 JSON 与列表，修改脚本常量后需重新运行场景。

`client/scenes/admin/data_browser.tscn`和`client/scenes/admin/world_overview.tscn`是**独立桌面开发工具，不是游戏内页面，也不随游戏导出**。数据管理页使用 **960×640桌面窗口和逻辑画布**，世界总图及其弹窗为960×540，可放大到1280×720等尺寸，不沿用手机画幅；世界总图采用地图与说明左右布局。按F6运行时自动将管理工具放到独立窗口，避开编辑器的手机比例宿主；也可用上面的命令行直接打开。世界总图可单独运行：`godot --path client res://scenes/admin/world_overview.tscn`。工具不修改游戏的320×480基础视口。

游戏导出使用`client/export_presets.cfg`中的`Game (Linux)`或`Game (Windows)`预设：明确排除`scenes/admin/`、`scripts/admin/`和`tests/`，保留游戏运行所需的JSON与共享资源。新增游戏预设时应保留同样的排除规则；完整可执行文件导出还需要对应Godot导出模板。导出边界验证见[tests/game_export.md](tests/game_export.md)。

物品目录收录 `item.mrp` 已解码的全部 **208 张图标：56 张武器、81 张装备、71 张其他物品**，可选择“原包资源”单独浏览，列表支持图标缩略图。原始资源编号、来源成员、帧号、尺寸、校验值均可查看；尚未恢复的原版名称、物品ID映射、等级和数值显示“—”。青锋剑、回春散另列为当前已接入的本地规则，预留装备槽位另作标记。同一原包资源会同时出现在“物品”和对应的武器/装备分类中。

重新导出物品索引与无损图标：`python tools/import_item_catalog.py`（使用 `analysis/image_manifest.json` 与已解码 PNG；修改原始解码结果后再运行）。

怪物目录同时收录 **6 条已接入的重建定义**和`monster.mrp`的**全部117份原始动画（覆盖142份图片成员）**，可按“已接入”/“原包资源”筛选。原包条目可查看图像、播放`source_N`原始序列并核对来源校验；资源编号不是恢复的怪物名称，原版名称、ID、等级及属性未知，117份素材不代表117种完整怪物定义。重新生成：`python tools/import_monster_catalog.py`。管理专用资源位于`client/assets/admin/monsters/`，不进入游戏导出。

特效分类收录`effect.mrp`**全部159份原始动画（覆盖75份图片成员）**，不再仅显示游戏运行时已导入的7份。支持原始序列播放与来源核对，名称和技能对应关系未知。生成命令：`python tools/import_effect_catalog.py`。

**原包归档不按能否解析筛掉条目**：包含6个MRP的1916条成员记录与1份原始版本文件，共1917条。已解析图片可切换全部帧，ANI可播放原始序列，文本可直接阅读；部分解析、未解析、空动画、解析失败或缺失源文件仍保留原始路径、大小、SHA256、目录记录、字节摘要和原因。按“已解析 / 部分解析 / 未解析 / 解析失败”筛选。生成命令：`python tools/import_resource_archive.py`；原始二进制仍保留在`analysis/`，管理专用预览不进入游戏导出。

地图页收录 Online 原包 `worldmap.data` 的 **214 条目录（157 个不同名称）**，并保留 3 条当前已接入的场景定义；可筛选“原包目录”或“已接入”。对照原生代码恢复了 **79 个世界总图位置、78条连线**，可展开查看、悬停查询名称与等级；目录还显示原包编号、位置、类型、原始记录与来源校验。单张场景地形仍缺少对应`.map`缓存，明确显示提示；[恢复记录与复现方式](analysis/recovery/maps/README.md)保留格式、扫描结果和证据。

“任务 / 线索”页区分一条重建任务链的 5 个阶段与 11 组原包界面文案、引导资料；原版任务总数仍未知。原包文字可在“文本摘录”页查看，文案和引导线索不当作完整任务定义。重新导出：`python tools/import_original_world.py`；该命令核验 Online 应用 ID 与原包成员，并同步生成 `analysis/catalogs/online_world.json` 和客户端只读索引。

## 服务器地址

封面选择“登录游戏”，输入目标服务器地址并“保存并连接”。支持`127.0.0.1:8080`、`game.example.com`或完整HTTP/HTTPS地址，也支持反向代理路径前缀。省略协议时IP/localhost使用HTTP，域名使用HTTPS。

有效地址保存到独立的`user://connection.cfg`，下次打开登录界面或重启客户端自动回填，可随时更换。连接失败也保留地址，非法输入不覆盖旧值，不保存密码或修改角色存档。

配置服务端数据库后，可从“注册账号”创建账号，再输入密码登录；会话仅保存在内存，可退出账号。登录后进入角色选择，可创建或查看服务器角色，再进入共享地图；每账号最多五个角色、昵称全服唯一，不导入或覆盖离线存档。地图中点击移动，底部“聊天”打开公共频道。公网账号要求HTTPS，本机回环地址允许HTTP。数据库配置见[server/README.md](server/README.md)。

- 优化行走滑步/倒退感：键盘连续移动不再每格插入待机，步伐按实际位移推进（32像素一整轮），跨格和转弯保留步伐相位。移动速度仍为每秒72像素，跨格保留本帧剩余位移，15/30/60/120 FPS速度一致；松键走完当前格后待机，阻挡和暂停不再空播步伐。
- 本地单槽存档；每10秒自动保存，任务和战斗结算保存，关闭窗口保存。覆盖已有角色前在游戏内提示。

推荐流程：创建角色 → 找道人领任务 → 背包装备青锋剑 → 击败三只山狼 → 道人领取奖励 → 东侧蓝色灵门 → 古剑遗迹妖王。可在道人处免费恢复生命和灵力。

战斗快捷键：**1**攻击、**2**技能、**3**待机、**4**道具、**5**查看、**6**逃跑、**0**自动/手动。点击人物或按Enter展开/收起指令菜单；“查看”卡片点击或Esc关闭。技能打开招式列表，按目录消耗灵力；待机恢复灵力5并防御，回春散恢复生命45。保留三个旧入门技能兼容，新增30个具名资料技能，支持流血、中毒、睡眠、反伤、回复等效果；本地和联机上限统一为60级。数值、自动解锁和当前限制见[技能接入说明](design/skills.md)。

## 资源重建

重建素材需要 Python、Pillow、NumPy：

```powershell
python analysis/decode_assets.py
python tools/import_assets.py
```

在仓库根目录执行以上命令，资源转换输出到`client/assets/`。`client/assets/data/actors.json`仅保存轻量索引，每个角色/特效的元数据位于`client/assets/data/actors/<分类>/<名称>.json`，游戏按需加载并缓存。原始310份ANI编排位于`analysis/animations/`（索引为`index.json`），不放入Godot客户端目录；导入报告仍为`client/assets/data/import_report.json`。仅重建JSON可运行`python tools/import_assets.py --metadata-only`，不会重写图片。导出游戏时需包含`assets/data/`下的全部JSON（如使用`*.json`非资源包含过滤器），不能只包含索引。ANI变换按低两位旋转、高位镜像的八种图像变换解释；人物idle选取静止姿态，walk采用原始行走序列，attack采用单次攻击序列，原始编号序列保留为 `source_N`。组合人物帧会按头部中心对齐Godot角色锚点，地图位移由寻路控制，原始层位移仍保留在分析JSON中。未恢复原客户端的动画事件和碰撞语义。

IMG/IMGS类型3是经过顺时针旋转存储的RLE图像。解码版本2会先逆时针转回正常方向，再应用ANI层变换；由此修正隐者头部侧倒及脚部散落的问题。标题图也使用统一解码，避免重复旋转。

默认玩家存档位置为 Godot 的 `user://shushan_save.json`；Windows一般位于 `%APPDATA%/Godot/app_userdata/蜀山剑侠 · 归来/`。
