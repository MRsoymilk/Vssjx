# 设计文档

[项目首页](../README.md) · [游玩指南](../docs/getting-started.md) · [贡献指南](../CONTRIBUTING.md)

本目录说明 Vssjx 的产品规则、实现边界与技术方案。**文档整理日期：2026-10-19**。“已接入”指当前仓库源码，不代表体验服、网页或 APK 已同步更新，也不替代测试验收。

## 阅读方式

- **当前实现**：优先阅读对应专题，结合源码、`shared/` 契约及迁移核对。
- **技术方案**：[架构](architecture.md) 和 [协议](protocol.md) 含目标设计，不能把类名、示例消息或规划目录当作现有 API。
- **未来工作**：[路线图](roadmap.md) 区分已接入、待验证和后续目标。
- **恢复证据**：`analysis/` 保留原始记录；重建规则和 AI 内容不能反向用作原版证据。
- **测试与发布**：命令、环境及历史结果放在 [测试目录](../tests/testing.md)，部署见 [部署导航](../deploy/README.md)。

## 当前能力与边界

| 领域 | 当前源码范围 | 不应由此推导的结论 |
|---|---|---|
| 客户端 | Godot 本地／联机双入口、独立存档、桌面／Web 平台接口 | 所有手机浏览器或原生设备已兼容 |
| 账号与角色 | PostgreSQL 账号、会话轮换、五角色槽位、全服昵称唯一 | 账号恢复、完整运营体系或账号级并发限制已完成 |
| 世界与战斗 | 权威移动、增量同步、NPC／任务、单人 PVE、组队多怪、邀请切磋 | 已恢复原服务器、原地图布局或原版战斗公式 |
| 社交与管理 | 公共聊天、资料、好友、基础帮派、本机管理与审计 | 交易、私聊、帮战、支付或完整运营后台已开放 |
| 资源与内容 | 原包静态恢复、重建物品、AI 世界及两系列新装备 | 每条目录记录都是完整原版定义，或素材已获再分发授权 |
| 部署与容量 | 单游戏写进程；已有网页／APK 发布和同步短测记录 | 当前全部源码已上线、世界集群或千人完整混合负载已验收 |

## 产品决策索引

D 编号用于追溯早期架构约束，不把历史确认等同于今天的代码或部署状态。规则已变化时，以明确标出的专题和迁移为准；未落实的目标继续列为缺口。

| 编号 | 方向与历史约束 | 当前说明 |
|---|---|---|
| D01 | 全服 1,000 人正常混合游玩；热点单独验证 | 仍为目标；[同步短测](../tests/capacity_delta.md)不等于完整玩法、公网或长稳验收 |
| D02 | 不自动分线，不按人数隐藏本应可见的玩家 | 当前同图全图互见、单进程；容量不足须如实说明 |
| D03 | 初期每账号一角色、一个有效游戏会话；同会话可重连接管 | 角色数量已由迁移 `0008` 改为最多五个；当前世界所有权按角色协调，不宣称已实现账号级唯一游戏连接，见[角色](characters.md)和[共享地图](shared_world.md) |
| D04 | 早期目标：断线冻结 60 秒、闲置 5 分钟按逃跑结算 | 非当前全部战斗共用规则；PVE 持久恢复、[决斗](player-duels.md)及[队伍](teams.md)各有现有行为，统一超时策略仍需核验 |
| D05 | 本地／联机双入口，资产隔离 | 不导入或覆盖线上资产 |
| D06 | 玩家互不阻挡，个人界面不暂停其他玩家与网络 | 私人暂停保护参数与完整状态机仍按具体实现验证 |
| D07 | 明确部署预算、地域、备份 RPO／RTO | 已有公网部署不等于备份恢复承诺已冻结；运维约定与演练仍需维护 |
| D08 | 全服昵称唯一；运营权限、审计和留存独立管理 | 名称由数据库约束；本机管理已接入，但完整恢复、留存与滥用防护未完成 |
| D09 | 单 Godot 客户端、平台接口及手机网页方向 | Web／原生导出已存在；手机真机和浏览器支持名单仍待验证 |

## 文档维护约定

专题尽量按“概述 → 当前状态 → 规则与限制 → 技术实现 → 验证入口与相关文档”组织。纯规范、候选方案、已接入资源和历史记录显式区分；更新状态时同步入口、相关专题与路线图，不仅在末尾追加进展。

设计文档不保存私有配置、密码或玩家数据，不以此前操作授权作为后续推送、打包或部署许可。原包、第三方和 AI 内容遵循 [来源说明](../docs/asset-provenance.md)。
