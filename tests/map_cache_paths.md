# Online 场景缓存路径与额外来源审核

目标：继续恢复可行走的原版场景；在缺少布局文件时，查明真实缓存命名及现有备份是否包含可用输入。没有改动Godot或服务端功能，不把总图、其他游戏地图或合成测试数据当作原版地形。

## 入口

```sh
python tools/audit_original_map_cache_paths.py --cache-root /path/to/mythroad --source /path/to/online-package.mrp --source /path/to/backup.zip
python -m unittest discover -s tests -p 'test_map*.py'
```

`--capstone-path /path/to/dependency`可选，仅生成静态Thumb证据；JSON审核不依赖Capstone。`--output`可另存快照。

## 检查范围

- 基于固定SHA-256的原生扩展，从真实字段1分派、包头文件名读取、最后扩展名移除、根目录与命名空间拼接推导缓存路径，不猜测以App ID或显示名称命名。
- 仅读取输入，ZIP不释放到文件系统，拒绝越界成员名、过多成员及超限文件/解压内容。保留原有解析器与有界gzip/zlib扫描规则。
- 其他App ID仅记录头部和目录名称以识别误认，不解压扫描载荷；用户排除的两个游戏路径直接跳过。额外同App ID变体仍标记需审核，不复制图片或地形进客户端。
- 以完整哈希识别重复文件、已核验原包及素材包；与主包不同的变体列出相同/不同/新增/缺失成员，原生代码不同则不套用已知地址证据。
- 对目标缓存目录和共享`cache/exr.*`仅读取、扫描，不把共享缓存直接归属Online。未知封装、碎片化内存及其他版本仍可能不能识别。

测试覆盖：实际包头内部文件名`ssjx.mpr`导出`gwy/ssjx/map`；移除最后扩展名；原生文件指纹与分派目标；证据片段哈希；缓存目录与其他游戏地图的区分；输入字节不变；排除路径；重复来源只处理一次；错误App ID不产生场景候选；ZIP路径逃逸拒绝。合成内容仅在临时目录中使用。
