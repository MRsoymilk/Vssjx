# 联网 NPC、怪物与个人试炼

## 阶段一：共享场景实体

青云山道加入清微道人、三只山狼和山灵。定义在`shared/data/qingyun-population-v1.json`，由服务端初始化并推进山狼巡逻，范围限制在出生点两格内，避开地图阻挡；NPC和山灵原地待机。客户端不启动本地世界或读取本地击杀状态。

支持的票据声明`population_version:1`，客户端在世界握手中选择该版本，服务端以独立的`population.state`发送完整有界居民状态；每个世界tick只编码一次，连接复用编码。新上线/重连收到当前状态，后续仅在居民修订变化时发送。玩家同步协议、在线人数和地图哈希保持原约定。

`online_resident.tscn`定义居民节点和姓名标签；原有`AnimatedSprite2D`负责待机/行走，山狼按服务端28像素/秒巡逻插值。小地图显示金色NPC与红色怪物点，玩家人数不包含居民。

阶段一验证：服务端120秒巡逻模拟通过（通行、邻接移动、两格活动范围、统一状态）；Godot协议/场景13项、实际OpenGL截图14项、同屏界面28项、移动控制35项通过。显示与巡逻是第一阶段；在线任务和战斗在下一阶段接入。

## 阶段二：在线任务与持久化战斗

- 票据协商 `pve_version:1` 后，通过认证世界连接接收私有 `pve.state`，发送严格的 `pve.command`，接收 `pve.result`。旧客户端无需启用此扩展。
- 清微道人提供“山林试炼”、恢复元气和一次性任务奖励；三只不同山狼分别计数，山灵提供额外遭遇战。各角色独立记录击败状态，同屏巡逻实体保持共享。
- 服务端校验会话、角色所有权、站立状态、目标距离和回合版本；客户端不能上报伤害、奖励或生命值。战斗中禁止移动。
- 角色进度、药品、战斗和操作回执在同一 PostgreSQL 事务中提交。相同操作 UUID 重试返回原回执；更改内容会冲突。断线和进程重启都能恢复未结束的战斗。
- `tests/run_online_pve.py` 使用隔离数据库验证三狼试炼与领奖、逐回合战斗、重复操作、旧回合拒绝、药品事务失败回滚、恢复、进程重启、角色隔离和连接接管。
- 规则测试覆盖绝技条件、满血用药、凝神、撤退、胜负与30回合上限。该阶段仅青云山道；2026-10-17 后续已接入古剑遗迹，参见 [联机第二张地图](online_maps.md)。
- 可使用 Docker PostgreSQL，或显式配置 `SSJX_TEST_PG_BIN` 与 `SSJX_TEST_PG_WORK_DIR` 启用测试专用便携 PostgreSQL；只清理自身创建且位于已核验测试目录下的临时集群。可用 `SSJX_TEST_SERVER_BIN` 指定独立构建的测试服务端。

## 阶段三：客户端任务与参考战斗界面

- 点击道人或怪物先沿权威地图靠近，等待站稳及移动确认。道人打开参照原视频的淡黄纸面对话选项，选择任务项接受/完成，恢复元气是独立选项；怪物直接进入挑战和遇敌准备，不再弹出额外蓝色确认框。
- `online_battle_view.tscn` 复用既有 `battle_hud.tscn` 与 `battle_inspect.tscn`；按用户参考保留右侧人物、左侧怪物、蓝色脚圈、原指针、黄纸竖向六项菜单和上下布局。六项依次为“攻击、技能、待机、道具、查看、逃跑”，技能/道具各有选择面板。战斗期间隐藏地图工具栏，底部原公共聊天区域继续收发消息与表情。
- 0键切换自动攻击；绿色选择倒计时到零会提交待机请求。按最新参考要求移除F加速与扳手按钮。回合结果仍由服务端判定，客户端不能修改伤害或奖励。
- `OnlinePve` 验证私有快照，按角色状态版本拒绝旧回执回滚当前进度；未确认的操作只保存在账号内存中，重新入场后用相同UUID和内容重试。退出登录清除该内存状态。服务端战斗与已提交结果不依赖客户端内存保存。
- 已击败的怪物仅在本人的刷新冷却期间从地图与小地图隐藏，其他角色仍能进行自己的试炼。2026-10-17 起胜利后默认 30 秒自动恢复，任务击败历史与当前冷却分离，见 `tests/online_respawn.md`。人物属性、进度与药品来自服务器，不写入单机存档。
- Godot `online_pve_test.tscn`：28项检查通过；实际渲染另验证截图。`online_pve_live_test.tscn`：13项真实 Rust/PostgreSQL 联调检查通过，包含界面自动接任务、追近巡逻怪物、战斗操作、战斗中聊天、丢失响应重试与重连恢复。
- 现有共享界面28项、移动控制35项、公共聊天48项、世界增量50项、人口显示13项均通过；Rust全量43项测试与Clippy通过。
- `SSJX_TEST_PVE_GODOT=1` 可随完整服务端集成测试运行真实客户端；`SSJX_TEST_PVE_CLIENT_ONLY=1` 只运行隔离数据库下的客户端联调。`GODOT_BIN` 需指向Godot控制台程序，`SSJX_PVE_CAPTURE_PATH` 可配置界面测试截图目录。
- 部署新服务端后，启动时自动运行0006数据库迁移。现有运行中的旧服务端未被测试流程停止或覆盖。


## 2026-10-17：联机直接交互与遇敌准备

- 删除“迎战／返回山道”和道人接取确认面板；地图空白点击、键盘移动、Escape、菜单、聊天及失去焦点均可取消尚未提交的接近目标。提交后仍由 `OnlinePve` 保存原操作 UUID，重复点击不能多次提交，断线只重试原操作。
- `online_encounter.tscn` 继承本地 `battle_encounter_transition.tscn`，复用角色旁的感叹号和金白边、蓝底青绿准备条。角色提示跟随画布位置，保留地图和底部聊天；覆盖层不阻挡聊天控件。
- 服务器回执未到时显示往返滚动条和等待文字，不宣称网络完成百分比。服务器确认战斗后，异步准备本人、怪物、打击及职业招式素材；进度来自真实资源请求和动作缓存准备。准备完成后自动进入战斗，无需再点击。加载阶段保持常规地图布局，战斗菜单和倒计时在进入战斗后启用。
- 读取失败保留服务器战斗，提示点击地图重试素材，不重新发送挑战。断线和离场取消资源消费者、推进准备代次，旧回调不能重新打开已离开的场景；加载中收到同一战斗的新版本使用最新权威状态进入。
- 视觉沿用现有本地实现。感叹号和边框仍是依据参考图程序绘制的复现，未声称从反编译恢复了完整原版联网加载流程。没有改动服务器战斗规则、奖励或单机任务流程。

## 2026-10-17：任务交互与战斗提示分离

修正此前复用遇敌提示导致“接受任务也像开始战斗”的问题，同时按用户本轮要求恢复 NPC 对话选项，不回退到早期的大蓝色确认框。

原版依据：

- 用户游玩视频已提取的 `11_NPC对话.png`：地图变暗，中央为金色角框、淡黄色纸面的 NPC 对话，蓝色姓名、招呼文字、任务行和其他交互行；没有战斗加载条。参考帧位于聊天工作区 `outputs/视频参考帧/`，视频信息在 `analysis/video_reference.json`。
- `analysis/decoded_text/ssjx/mission.txt` 的原包界面文案包含“接受”“完成”“已接”“任务目标”“任务描述”。本轮任务选项采用“接受/完成”的动作语义。
- `analysis/catalogs/online_world.json` 中 `teach1` 原包文案明确：头顶黄色感叹号代表有任务可接受。NPC 有未接试炼时显示黄色标记，接受后隐藏；怪物不显示任务标记。

实现：

- `npc_dialog.tscn` 与 `OriginalNpcDialog` 独立于战斗组件。走近道人仅显示对话，选择任务项才提交接受/完成；进度显示在任务行，恢复是另一行。每个操作重新等待站稳及移动确认，等待/重连文字留在对话内部，禁止重复提交。点击外部或 Escape 可关闭。
- 成功回执关闭对话并更新任务标记；错误保留对话中的说明。未确认操作仍按原 UUID 重试；只关对话不能伪造任务成功或取消已经提交的服务器事务。
- 后续地图任务标识修正：本地与联机共用 `npc_quest_marker.tscn`，姓名移除固定“ · 任务”，可接和可交付时显示黄色感叹号；接受、交付、断线时按状态收起。依据和验证见 `tests/quest_markers.md`。
- `OnlineEncounter` 只接受 challenge；NPC 的 accept/claim/restore 不再进入红色遇敌爆炸图标、滚动等待条或战斗资源准备。怪物挑战、加载与回合流程保持原实现。
- 对话布局参照视频；金角复用现有项目 SVG，并非本轮恢复原生对话绘制函数。“清微道人／山林试炼”的文本、规则、奖励仍是现有重建内容，不声称恢复了原版任务定义或服务器脚本。原生单机对话逻辑未在本轮重写。

Windows / Godot 4.7.1 验证：界面59项、实际 OpenGL 渲染65项、隔离 Rust/PostgreSQL 联调25项通过；人口13项、移动35项、聊天48项、本地遇敌131项、双模式1048项回归通过。验证覆盖接近后只打开对话、明确选任务才提交、任务操作无战斗提示、黄色标记随状态更新、已接进度、独立恢复、完成选项、重复操作与断线重试，原怪物遇敌准备仍通过。
