# 联机防作弊、用户管理与持久审计

## 已有边界与本次加固

接口会写入数据库，但只接受白名单业务意图，没有任意 SQL 或任意角色字段更新接口。

- 登录凭据为随机令牌，数据库只存摘要；密码使用 Argon2。每个角色/操作回执/入场票据都校验账号归属，账号和会话被撤销后不能继续操作。
- 客户端不能提交金币、经验、血量、伤害、角色等级或最终位置。严格反序列化拒绝额外字段。移动路径、速度、战斗回合、装备加成、任务状态、怪物刷新与奖励均由服务端计算；单机存档不会导入联机角色。
- 数据库事务、角色版本、战斗版本、所有权世代和UUID操作回执防止并发覆盖、过期连接写入、重复结算和同一操作号篡改意图。
- 在原有认证/连接/聊天限流之外，增加账号级业务预算：一个账号的所有角色、所有连接与所有服务进程共享 **180次 PVE 命令 / 60秒窗口**，包括重复请求。预算在数据库中维护，重连与重启不重置；这是业务滥用上限，不是战斗动画的回合计时器。窗口耗尽每分钟最多新增一条预算拒绝审计。数据库异常导致事务回滚时，预算也回滚。
- 注册、登录成功、令牌刷新、注销、创建角色、PVE业务、管理员封禁/解封/强制下线均在同一数据库事务写入审计。审计失败则该业务及回执一起回滚。PVE记录目标、结果、金币/经验/等级/血量/灵力/任务/装备/消耗品/属性/战斗状态的前后值；重复请求只记“未变更”。
- 登录失败、已认证连接的非法协议/PVE前置拒绝、进出地图、每10秒的移动数量及拒绝码汇总采用尽力持久记录，数据库不可用时只记录固定运行错误；不承诺数据库故障期间仍能完整保留这些观察事件。未认证的恶意握手、无效JSON等仍由已有运行错误计数/限流覆盖，不将每个无身份垃圾包写入数据库。
- 带有效登录凭据的HTTP拒绝也可归属账号，包括跨账号读取、非法创建字段、尝试PATCH未知资产接口等。只记录方法、路由模板、错误码、状态与服务端请求ID，不记录原始路径/参数。诊断写入按认证限流窗口（默认60秒）限制为全局120条候选、单账号20条，超额仍拒绝请求但不逐条入库；运行错误计数继续累计。
- 所有 SQL 参数绑定；不采信客户端声明的账号ID、伤害、奖励、发送者、代理IP。登录审计的 `transport_peer` 是实际TCP对端：经过本机隧道时通常是127.0.0.1，不能据此认定真实玩家IP。

设计依据：[OWASP对象级授权](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)、[敏感业务流自动化滥用](https://github.com/OWASP/API-Security/blob/master/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows.md)。客户端隐藏接口、加密参数或混淆代码不能代替服务端授权。合法账号仍可能自动化执行合法动作，本次不宣称杜绝脚本或所有作弊，也不依据单次拒绝自动封禁。

## 管理网页

更新服务端并应用迁移0011后，在服务主机打开 **http://127.0.0.1:9090/**。不需要重新打包Godot网页或APK。当前任务不部署、不重启现有服务、不修改现有玩家数据库。

页面提供：用户名、角色名（支持中文部分匹配）、账号/角色ID查询（每页50个）、角色与物品只读详情、最近20条会话元数据、按账号/角色/结果筛选审计（每页100条，以ID翻页），以及填写原因后的封禁、解封、强制下线。用户列表同时显示总用户（账号）数、搜索匹配数、本页数和总页数；包含封禁账号，不把角色数、有效会话数当作用户总数。计数与分页来自同一只读数据库快照，空搜索结果和超出范围的页码仍返回正确总数。封禁/下线撤销全部会话，现有世界连接通常在下一次会话检查（约1秒）断开；解封不恢复旧令牌，需重新登录。有效会话数量不等于实际在线人数。

管理中心按功能拆页：`/`服务概况、`/users`账号与角色列表、`/users/{account_id}`账号/角色详情、`/audit`操作审计、`/announcements`全局通知。侧栏在各页之间切换；面包屑显示“管理中心 → 用户管理 → 账号 → 角色 → 操作审计”等上下文。详情面包屑返回列表时保留查询词和页码；审计筛选保存在URL，支持直接打开和刷新。每页只加载自身内容与数据，不在隐藏页面执行管理请求。

按角色处理时，点击角色名后突出显示该角色，提供角色操作记录入口；封禁/解封/强制下线仍是**账号级操作，影响账号全部角色**，页面和确认框均明确提示。请求可带选中的`character_id`，服务端在操作事务中验证其归属，审计记录选中角色以及实际`scope=account`。不提供通过角色检索越权更换目标账号的接口。

这些接口只挂在独立运维监听，不挂到8080/8000公开游戏入口：

| 接口 | 功能 |
| --- | --- |
| `GET /api/users?q=&offset=0` | 按角色名/用户名/账号或角色UUID检索；返回账号、角色摘要及进程CSRF令牌 |
| `GET /api/users/{account_id}` | 白名单账号、角色、物品、会话详情 |
| `GET /api/audit?account_id=&character_id=&outcome=&before=` | 持久审计，过滤参数均可省略 |
| `POST /api/users/{account_id}/actions` | `operation_id`、`action`、`reason`、可选`character_id`上下文；action仅disable/enable/revoke_sessions |

所有请求要求实际回环TCP对端、回环Host、同源/无跨站浏览器标识；写操作额外要求精确同源Origin、`X-Operator-Token`随机进程令牌、UUID v4意图和2～240字原因。管理员回执按操作号去重并比对意图。页面在请求结果未确认时，保留操作号；同一账号、动作和原因的重试沿用原意图，避免断网后重复执行。同一主机上的可信用户均可操作，没有多管理员权限分层；**不要将9090映射到公网**。需要远程管理时使用已有SSH隧道。游戏账号Bearer不能作为运维授权。响应为no-store，CSP拒绝外部脚本/嵌入，动态文本使用textContent。

## 数据与运行限制

迁移0011新增 `security_audit`、`gameplay_budgets`、`operator_receipts`。审计记录不依赖会话外键，过期会话被清理后仍保留归属。索引覆盖账号/角色与时间；详情限制16KiB，查询有分页上限，不记录密码、摘要、Bearer、票据、原始请求或聊天正文。

普通UPDATE/DELETE受追加写触发器保护，但数据库所有者/超级用户仍可删除触发器、TRUNCATE或直接改角色表；这不等于防篡改日志。数据库密码泄露、主机被控制不在游戏API授权能够独立解决的范围。Compose默认只向127.0.0.1绑定数据库端口；生产环境还应把迁移账号和运行账号分开、运行账号禁止DDL/超级用户权限，并将审计备份到服务账号不能修改的位置。当前迁移仍沿用项目既有数据库角色，不自动修改生产权限/密码/防火墙。

审计不随进程重启或运行日志轮转清理。移动采用汇总以控制写入量，仍需监控数据库容量并确定留存/归档政策；本次没有擅自删除历史数据或上传外部服务。
