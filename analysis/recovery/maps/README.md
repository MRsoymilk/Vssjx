# Online 原版地图恢复（2026-10-16）

来源限定为 `analysis/source/ssjx.mrp`，App ID **403084**、版本48。两个被用户排除的同名游戏没有参与资源导入。只做静态解析，不执行 ARM 扩展、不连接旧服务器。

## 已恢复：世界总图

`worldmap.data` 的3,592字节均可对应到目录和总图结构。恢复出214条目录记录（157个不同名称）、79个可见地点位置、78条原包绘制线段；其余135条目录的位置为隐藏值。

| 数据 | 原始格式 | 原生代码依据（文件偏移） |
|---|---|---|
| 总图头 | u8 行数25、u8 列数22、u8 目录数214 | `gameonline.ext@0x2b25c` |
| 名称 | 214组：u16大端字节长度 + UTF-16BE文本 | 同上，调用 `0x27940` |
| 地点记录 | 214×6字节：编号、行y、列x、类型、最低等级、最高等级 | 读取 `0x2b25c`；绘制 `0x21244`；等级 `0x2193c`；编号查找 `0x221e8` |
| 连线 | u8 数量78，随后78×4字节：起点行、起点列、终点行、终点列 | 读取 `0x2b25c`；绘制 `0x21090` |

地点类型0/1/2分别使用原包 `worldmap` 图集的野外、城市、门派图标。管理页复制的是已解码的原始图标，没有重画。坐标已转换为x/y，避免行列颠倒；两坐标均为255的记录保持未知位置。

保留两处原始异常，不补造地点：第75条线段（零起索引74）连接 `[22,12]` 与 `[22,8]`，超出头部声明的列范围且两端没有名称；第78条（索引77）为 `[15,12]` 到自身的零长度线段。总图预览扩大显示边界以容纳原始端点，原始尺寸不变。这些线段**不能直接当作完整通行、传送或场景连接配置**。

管理页地图分类可查看全部目录的编号、位置、类别与等级，点击“展开世界总图”查看全图，悬停显示地点详情。世界总图与单张场景地形分别标明。

## 单张场景：恢复出候选格式，尚无真实样本

`0x137c8` 生成 `%d.map` 缓存文件名。其读取流程推导出的主体如下；**真实样本尚未取得，合成测试不能证明原包场景已恢复**。

| 顺序 | 字段 | 格式 / 依据 |
|---|---|---|
| 1 | 原包地图编号 | 带i16大端字节长度的UTF-16BE数字字符串，`0x27964` |
| 2 | 场景名称 | 带i16大端字节长度的UTF-16BE文本，`0x278f0` |
| 3 | 行数、列数 | 各1字节；原生读取后存入/取出为无符号字节 |
| 4 | 地形层 | 行×列字节，`0x1381c`；0不绘制，正索引查图块表 |
| 5 | 通行/交互层 | 行×列原始字节，`0x13824`；位含义尚未完全恢复，不能简单“非零即阻挡” |
| 6 | 图块表 | u8数量 + 该数量的i16大端数组，`0x2fb50`；编号减1生成`tile%d`，`0x15618` |
| 7 | 两个元数据字节 | 各i8，`0x13856`、`0x1385c`；业务含义待核验 |
| 8 | 交互记录 | i8数量，随后每项两段UTF-16BE文本 + i8列x + i8行y，`0x13862`；两个文本的业务含义待核验 |

图块绘制为16×16像素，证据 `0x14670`。缓存读写 `0x25430` / `0x27274` 支持前置4字节校验值；扫描器尝试原始载荷及跳过4字节的载荷，**没有服务端期望值，不能据此验证校验值或来源身份**。

解析器为保守候选筛选：编号/名称必须对应已核验的Online目录，图块表必须落在现有756张原图块范围，地形索引须有效，交互坐标须在场景内，尾部须完整消费。不支持未知版本、额外封装、未解析尾部或其他尚未识别的变体，未匹配不等于证明这些文件绝无地图内容。输出候选一律标记需审核，不自动导入游戏。

本轮扫描 `analysis/unpacked` 的1,928个文件及内存卡中排除两款游戏后的3,921个文件，没有找到符合以上格式的载荷。内存卡111个MRPG包头中没有App ID 403084。扫描检查已有解包成员和散落缓存；不把其他App ID的压缩包当成Online资源。原包 `map.mrp` 现有756张地形图块与装饰，未发现编号 `.map` 布局文件。因此**214张单独场景地形、碰撞、NPC和任务配置仍未恢复**；继续恢复需要真实Online场景缓存，或可核验的布局数据。

## 复现与证据

在仓库根目录运行：

```sh
python tools/import_original_world.py
python tools/recover_original_maps.py --scan-root /path/to/mythroad
# 可选：静态反汇编证据，依赖capstone；仅读取本地二进制
python tools/disassemble_original_maps.py
python -m unittest discover -s tests
godot --headless --path client res://tests/data_browser_test.tscn
```

- `native_evidence.asm`：12处相关Thumb代码片段；地址均为文件偏移，非运行时地址。部分片段包含文字池，不能将其中数据当作指令语义。
- `native_evidence.json`：原生文件SHA-256、片段边界、每段字节SHA-256和分析说明。
- `recovery_report.json`：扫描范围、文件数、包头身份统计和候选数。脚本只读扫描目录，仅写入分析报告。
- `analysis/catalogs/online_world.json` 与 `client/assets/data/original_world.json`：一致的目录、解析字段、原始字节、路线及来源。
- `tests/test_original_world.py`：逐字节回拼、坐标方向、异常线段保留、原图标一致、来源身份与证据哈希。
- `tests/test_map_recovery.py`：明确标为合成的内存数据测试，不导出任何假场景为项目资产。
