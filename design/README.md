# Vssjx 联机版设计

设计修订：2026-10-15。已实现账号、角色、单次入场票据、青云山道多人同图移动和公共聊天，包括会话所有权、重连及位置保存。共享增量同步v2已接入；千人容量验收另见[测试计划](../tests/online_test_plan.md)，不以功能接入作为容量达标结论；线上任务/PVE、完整混合负载及公网长稳仍在后续阶段。当前世界仅支持一个服务进程；公网WSS需由TLS反向代理终止。

## 1. 已确认的产品范围

- 联网目标为多人同地图，而不是仅上传本地存档。
- 首版支持账号进入服务器、共享地图、独立PVE战斗、个人任务怪和公共频道聊天。
- 后续部署到公网，以全服1000人正常混合游玩为容量目标；单实例热点容量独立验证和报告，不要求以1000人同一可见范围作为同一验收口径。
- 客户端使用Godot；服务端采用Rust模块化单体、PostgreSQL、HTTPS/WSS，不提前引入微服务。
- 当前已有客户端目录迁移、服务器地址记忆、Rust服务发现、账号认证、角色大厅/创建回执、共享地图权威移动及公共聊天；线上战斗与任务尚未接入。

## 3. 首版边界

首版沿用现有两张地图及离线任务链，完成以下流程：

```text
注册/登录 → 创建或选择角色 → 进入共享地图 → 移动/公共聊天
    → 与个人任务目标交互 → 独立PVE → 领取奖励 → 保存与重新登录
```

暂不建设交易、组队、帮会、PVP、共享Boss、跨服、支付及完整运营后台。基础管理仍需禁言、封禁、日志查询和备份恢复。现有界面中的邮件、社交、合成及未实现数值不因联网而自动成为首版功能。

原版服务器和战斗公式没有恢复。联机服务基于当前原型的重新编写规则建设，不宣称还原原版服务端。不上线可修改的本地存档资产，不擅自增加怪物刷新、重复任务或数值调整。

## 4. 本轮技术设计约束

角色业务由独立于连接生命周期的`CharacterActor`统一协调。连接切换不能抹掉已经受理的事务；战斗与背包不能各持一份可独立写回的库存。已提交的业务通过回执和快照恢复，不依赖客户端动画、确认消息或旧连接是否还存在。

需要持久化的命令先查幂等回执，再对新操作检查状态版本。战斗开始、每个有效回合、最终结算、任务领奖和关键切图均有明确事务边界。普通行走的宽松保存不能覆盖关键切图或战败回城。

分批快照有完整性边界和增量衔接；连接代次、世界代次、订阅流序号和业务修订各司其职。在线界面只能经业务接口请求操作，不能继续执行离线结算。

以上为本轮采用的技术设计，不代表代码已实现；产品规则仍按下面的决策表处理。

## 5. 产品决策与待办

2026-10-15用户确认：**D01～D06采用建议方案；D08中的角色昵称不允许重名**。下表区分已确认规则与仍待确认的部署/运营项，不把确认设计等同于功能已经实现或容量已经达标。

| 编号 | 事项 | 决策/待办 | 状态与实施关口 |
|---|---|---|---|
| D01 | 容量目标 | 全服1000人正常混合游玩；单实例热点单独验证和报告，不以空闲连接替代 | 已确认；M3前冻结具体负载，M5验收 |
| D02 | 分线与可见人数 | 首版不自动分线、不按人数隐藏本应可见的玩家；容量不足则报告实测限制并重新决定，不暗中降低互见范围 | 已确认；M2～M5保持约束 |
| D03 | 角色数量与重复上线 | 每账号一个角色、一个有效游戏会话；同一登录会话允许重连接管，不同登录会话拒绝第二次上线，不自动顶号 | 已确认；M1实现 |
| D04 | 战斗断线与闲置 | 断线冻结60秒并停止自动下指令；超时按主动逃跑结束，保留已提交消耗、不发胜利奖励；在线无有效指令5分钟同样结束。窗口由服务器计时，单纯反复重连不能延期 | 已确认；M2实现并验证边界 |
| D05 | 离线入口 | 保留离线与在线双入口，存档完全隔离，不自动导入线上 | 已确认；M1接入 |
| D06 | 碰撞与个人页面表现 | 玩家互不阻挡；战斗时原地显示“战斗中”；打开个人页面只停本人输入和个人怪物，网络及其他玩家继续更新。私人暂停需服务端确认并有次数/时长保护 | 已确认；M2实现，保护参数配置化验证 |
| D07 | 部署与备份 | 部署地域、服务器规格、月预算、最大可接受数据损失量（RPO）及恢复时间（RTO）尚未选择；先记录预算/地域，再按压测选型 | 待确认；M5前 |
| D08 | 名称及运营规则 | **线上角色昵称全服唯一，不允许重名**，不按地图/实例分别占名；唯一角色ID仍是业务身份，不用昵称作主键。聊天历史/审计保留期、账号恢复及管理权限仍待确认 | 名称规则已确认，M1实现；运营项待确认，M5前 |

D04不增加额外惩罚：主动逃跑沿用当前保留已消耗资源、没有胜利奖励的规则，不套用战败回城处罚；服务器维护和可确认的服务端故障暂停不应冒充玩家断线触发处罚。60秒断线窗口和5分钟闲置期限是已确认产品值，写入版本化配置，不作为可随压测任意调整的性能参数。

D08的昵称唯一性由服务端校验和数据库唯一约束保证；客户端查重只提供提示，不能代替并发防护。现有离线昵称不参与线上占名，也不批量修改旧离线存档。首版不因此新增在线改名、角色删除或名称释放功能。

除上述已确认产品值外，各文档中的频率、消息/队列限额、延迟门槛和未定保护参数仍为起始技术建议，需配置化、记录到测试环境并经实测确认。D07及D08运营项只阻塞相应公网发布关口，不再以“等待D01～D06/昵称确认”阻塞M1、M2实施。
