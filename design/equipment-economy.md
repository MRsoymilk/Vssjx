# 装备掉落、绑定与玩家交易

[返回设计索引](README.md) · [商城目录](shop_catalog.md) · [组队](teams.md) · [交易验收](../tests/economy.md)

性质：**当前源码规则**，核对至2026-10-27。装备数值、原生外观映射与交易机制均包含重建规则，不声称恢复原服务器掉落表；源码实现不等于体验服或APK已更新。

## 装备来源与随机掉落

- 当前商城目录459项，其中装备模板383种：`original/` 137种、`ai/` 241种、兼容固定装备5种。原生模板复用原包图标与人物部件；武器、衣服、头饰影响人物组合外观，其余槽位主要体现图标与属性。
- 普通遭遇25%概率掉一件，普通掉落保底间隔8场；首领／精英两件，15级以上每8个首领保底一件流派装备。整场只结算一次，不按增援、复活或重放次数重复发装。
- 掉落职业独立随机，不采用拾取者职业或性别；部位随机，原生／AI外观池各50%。模板仍须与本次随机生成的职业／流派兼容，因此不是对383种模板逐件等概率抽取。
- 物等按遭遇奖励等级生成并限制在1～60级，普通遭遇通常取怪物等级，无尽试炼使用本轮冻结等级；不再按拾取者等级降低物等。可以持有、领取和交易自己暂时不能穿戴的装备。
- `progression-v1.json` 的 `original_appearance_percent` 控制原生来源比例。旧 `focus`／`focus_percent` 保留兼容读取，但不参与抽取；`gear_focus` 返回 `RANDOM_DROPS_ONLY`，界面不开放定向操作。
- 新掉落实例拥有独立UUID、物等、品质、词条及可选传奇／套装标识；保存已抽结果，重连或重启不重新抽取。双端随机实现必须一致，联机不接受客户端提供的种子、价格或物品数值。

## 穿戴与绑定

| 状态 | 行为 |
|---|---|
| 新掉落 `bound=false` | 未穿戴时可以进入玩家交易或拍卖托管 |
| 首次成功穿戴 | 校验职业、性别、流派、等级及状态后，将穿戴和 `bound=true` 一起持久化 |
| 穿戴拒绝或保存失败 | 不提前绑定，不改变原库存与资源 |
| 卸下已绑定装备 | 不解绑，不能重新交易 |
| 历史实例缺失绑定字段 | 保守视为已绑定；不猜测过去是否曾穿戴 |
| 原固定商城装备及其旧库存镜像 | 继续原固定装备规则，不变成可交易的新随机实例 |

职业、性别、流派及等级是**穿戴条件**，不是入包条件。强化／洗炼不代替穿戴绑定，旧UUID和词条不因升级规则而重抽。

装备评分读取 `equipment-score-v1.json`，是基础属性、强化和词条的派生显示值，不写入库存、不代替服务端战斗属性，也不等同于售价或流派价值。传奇／套装效果单独展示，详见[装备评分](../tests/equipment_details.md#装备评分2026-10-27)。

## 单人与组队分配

- 单人奖励先入背包，满包进入暂存；原十槽、60格背包与20格暂存规则继续生效。
- 新组队公共池只生成一份装备份额，所有实际参战者均可ROLL，不按收件人的职业、性别、等级筛选。未参战者不能分装；倒下或参战后离线不剥夺已有获奖资格。
- 每件分别ROLL／放弃；服务端生成1～100点，最高者获得，同点自动加骰。60秒未选自动放弃，全员放弃则无人获得；队长不能指定赢家或决定掉落部位。
- 新池使用 `unrestricted=true`；历史在途池保留已冻结资格。发奖仍校验实例合法性、唯一归属和容量，但不再以角色等级拒收高物等装备。
- 分配未完成前禁止下一场或破坏队伍结构；最后选择、发奖、回执与审计同事务提交。具体兼容及验证见[公共ROLL](../tests/team_loot.md)。

## 拍卖行

入口：**联机菜单 → 交易 → 拍卖／上架／我的／领取**。不生成离线买家，不连接本地存档资产。

| 项目 | 当前规则 |
|---|---|
| 可上架物品 | 背包内未绑定、未穿戴、非旧固定装备 |
| 上限 | 每角色同时20件 |
| 货币 | 铜钱；起拍价1～10亿，一口价不低于起拍价且不超过10亿 |
| 时限 | 6／12／24小时 |
| 最低加价 | 当前出价的5%向上取整，至少1铜；首拍从起拍价开始 |
| 费用 | 当前不收手续费 |
| 自买与撤回 | 不能购买自己的拍品；有出价后卖家不能撤回 |
| 被超价 | 原出价进入持久化待领取，不重复直接加回钱包 |
| 最高出价者加价／买断 | 只补已托管出价之外的差额 |

上架将原实例移出背包进入托管，竞价将铜钱移出钱包。到期有出价成交，无出价退回；后台每30秒批量补结算，请求前也补结算，不保证到期瞬间已送达界面。成交、撤回、退款及到期物资进入“领取”，装备UUID、词条和未绑定状态保持不变。

## 当面交易

入口：**交易 → 当面 → 输入完整角色名邀请**。

1. 双方在线、同图2格内且停稳，对方接受邀请；每人不能同时进入多笔未结束交易。
2. 各提供最多6件未绑定装备及0～10亿铜钱，资源立即进入托管，不能同时花费、穿戴、分解或上架。
3. 双方分别锁定报价，然后分别最终确认；任一方改报价会清除双方锁定与确认。旧修订上的确认拒绝执行。
4. 两份最终确认齐全后，在同一事务中完成双向交付，物资进入对方“领取”页；交易本身不绑定装备。
5. 任一方可取消，对方离线时也能取消。10分钟未完成到期退回原提供者；仍通过后台或请求补结算处理。

邀请通过私有PvE快照提示，不是公共聊天。战斗、灵魂及离线角色不能发起交易操作；交易进行期间不保证角色不能进入其他玩法，未完成托管仍受取消和到期退回保护。

## 领取、持久化与接口

- 领取装备先尝试背包，满包进入暂存；两者均满、或货款导致钱包溢出时拒绝本次领取，保留原待领取记录。每次快照最多展示50条未领取记录，领取后继续显示后续记录。
- 有进行中拍卖、出价、当面交易或未领取物资时阻止删角，避免资产或退款失去收件人。
- `POST /api/v1/economy` 通过Bearer认证、角色归属、世界业务门、数据库事务及审计处理。动作包括 `snapshot`、`list`、`bid`、`buy`、`cancel`、`claim`，以及 `trade_invite`、`trade_accept`、`trade_offer`、`trade_lock`、`trade_confirm`、`trade_cancel`。
- 写入使用UUIDv4操作号，完整请求摘要绑定回执。网络结果未知时只重试原请求，不能更改价格、对象或内容复用操作号；变更请求冲突，失败事务不发布成功回执。
- 拍卖和当面交易的对象修订与PvE角色修订不同，不能混用；价格、点数、归属和最终库存始终以服务端结果为准。
