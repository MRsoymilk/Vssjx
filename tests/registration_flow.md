# 注册与原角色创建场景

线上入口的注册使用登陆页填写的账号和密码创建服务器账号，成功后用同一组凭据执行真实登陆，再进入 `res://scenes/ui/character_creation.tscn`。原场景保留六个角色、AnimatedSprite2D预览、昵称、随机改名和介绍；额外的账号标识、门派选择、请求状态和返回按钮也在该tscn中定义。

`OnlineCreationFlow` 仅在该场景启用 `online_mode` 时工作。角色由服务器创建并绑定当前账号，不调用本地 `Game.new_player` 或覆盖本地存档。登陆时先重新读取该账号的服务器角色，已有角色直接进入同屏地图，无角色才继续创建。退出创建保留内存中的登陆会话，可从账号页继续。

注册和登陆仍是服务器的两个接口，客户端只在注册过程中暂存密码以完成自动登陆；登陆请求发出、注册失败或离开页面时清除此临时字段。密码、令牌、线上角色均不写入连接偏好文件。下次启动可用注册的原账号密码登陆。服务地址 `local` 的无账号单人流程不变。

昵称冲突保留选择并允许修改；结果未知保留原操作ID及创建内容，冻结昵称/职业/性别/门派，使用原创建按钮重试。读取失败也可用该按钮重试，登陆过期则返回账号页重新登陆。

## 本机协议验证

```sh
python tests/run_registration_flow.py
```

`GODOT_BIN` 可指定Godot路径。该脚本只启动回环HTTP夹具，不读取生产配置或连接生产数据库，运行注册导航、角色创建和账号会话三个Godot场景，检查真实HTTP请求、账号归属、同一角色的再次登陆、昵称冲突、提交后丢失响应/提交前失败的原请求重试、返回/重开、自动刷新、登陆过期、重复操作锁定及本地存档隔离。`--render` 使用真实渲染；可通过 `SSJX_REGISTRATION_CAPTURE_PATH` 保存创建页面截图。

完整服务器数据库验证仍使用 `tests/run_account_auth.py` 和 `tests/run_characters.py`，需要Docker PostgreSQL。HTTP夹具不证明数据库持久性、服务器事务或世界同步。
