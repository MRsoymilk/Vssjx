# 玩家决斗验证

[设计规则](../design/player-duels.md) · [测试总览](testing.md)

## 入口与隔离

`server/tests/duel.rs` 覆盖规则、权限、重复请求、技能、超时与断线。运行规则测试：

```sh
cargo test --locked --manifest-path server/Cargo.toml --test duel
python -X utf8 tests/run_duels.py
```

集成脚本使用一次性 PostgreSQL 和真实 WebSocket；设置 `GODOT_BIN` 后分别验证邀请者／接收者实际界面，另一方使用独立协议客户端。`SSJX_DUEL_RENDER=1` 启用渲染与截图，Godot `res://tests/duel_test.tscn` 另覆盖界面及本地存档隔离。不把连接参数指向玩家数据库或正在使用的服务。

覆盖拒绝写库失败、五分钟冷却、重启后保留冷却、越权确认、共用决策编号、首人锁定但不执行、不泄露对手指令、提交顺序不影响先手、敏捷排序、同速裁决、防御优先、先手击倒／封印／吸蓝、30 秒补防御、50 回合上限、有序双动作播放、PVE 隔离、常规资源不变、已提交后短线恢复和认输。上线需要客户端、服务端及 `0017_duel_cooldowns.sql` 配套。

## 同时决策版本

`duel_version=2`：客户端的“能否选择”依据规划阶段、本人锁定状态和服务器截止时间，不能再把 `turn` 当成输入权限。测试用真实服务和一次性数据库，UI 通过角色资料中的“邀请决斗”按钮进入。

## 已提交后的等待界面

本人提交指令后收起六项指令菜单，中央显示“正在确认指令…”；服务端确认后改为“等待对方操作”，保留次要的认输按钮。点击人物不能重新打开已锁定菜单。开始结算／播放、断线恢复时隐藏等待面板；下轮可以操作时恢复原菜单；重连到已提交的回合恢复等待提示。协议和服务端规则不变，只需重新运行更新后的客户端。

`duel_test.tscn` headless46项、实际OpenGL49项通过，含确认前后、人物点击、下一轮恢复、回放隐藏、重连与认输提交。截图在忽略目录`work/duel-waiting/pk-waiting.png`，已人工检查。`online_pve_test.tscn`71项断言通过；其退出仍有既有ObjectDB4项／resource1项清理警告，不作为本次修复成果。没有更新运行中的服务或重新导出客户端。
